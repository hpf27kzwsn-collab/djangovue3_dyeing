当前实施与验证范围见[第三批实施记录](2026-10-16第一阶段剩余基础与平台业务实施记录.md)、[核验结果](erp-foundation-completion-verification-20261016.json)、[运行接口检查](erp-foundation-completion-runtime-20261016.json)。E105～E113逐项记录明确合理替代及无法原样执行的旧逻辑。

后续开发按以下顺序继续，已完成的代码不重复重写：

1. P1验收尾项保持在台账：四项中控Lookup缺原外库；编号预览与正式占号的区别、原无序/字符排序/动态文本协议、19视图完整历史及旧客户端自动时点均逐项保留。无证据的组织/主体/机台工厂关系仍保存原码和全部候选，不伪造唯一对应。
2. 进入P2销售报价/订单与打样配方的剩余对象，复用当前基础服务；优先检查新增函数在原保存、审核、修改、失效和逆向中的实际调用。
3. P3～P5依次补齐采购外协/库存、生产执行、质量包装交付及整链逆向；低频、异常和历史变体继续保留。
4. P6继续逐入口补参数、投影、公式时点及打印/客户端协议，包括未恢复的其他平台日志、模板、通知及配置表；P7处理外部联调；P8推进完整历史采用和全链对照。原配置留存与激活为新系统配置分别办理。

后续按基础资料与共享来源 → 销售订单/打样配方 → 采购外协及库存 → 生产执行 → 质量包装交付与整链逆向 → 全入口及平台调用补齐 → 外部联调 → 历史接续和全链验收推进。异常、旧版、试验版、空表和少用业务保留在分母中；规则有原证据按原规则，没有原证据按明确合理实现登记差异，不额外增加未经证明的限制。

## 2. 业务先后关系

### 2.1 订单、工艺与备料汇合

业务通常按以下关系展开，打样和备料可以与商务录单穿插进行：

```text
报价/确价 → 销售订单与订单明细 → 订单需求确认
客户来样 → 多轮试验 → 送版/客户回复 → 确板色号与配方版本
已有色号/已确板配方 → 本次订单选择采用
采购申请/采购单 → 到货与批次 → 来料检查 → 入库可领用
客户来料 → 货权与批次登记 → 来料检查 → 入库可领用
在库坯料/半成品 → 本次订单或工卡备料
                          ↓
订单需求 + 有效路线 + 对应工艺 + 实际物料来源
                          ↓
工卡建立/下达 → 订单数量分配 → 拆卡/组缸 → 排程
```

订单确认不强制每次新建打样；沿用已确板色号时记录所选版本。来样单可以在订单前建立，也可以关联已有订单。客户来料可以先入库，之后按明确工卡领用；库存不足不等于不能先建计划，但实际领料与开工要满足对应节点的条件。

非染色的独立松筒、加捻任务采用各自路线，按需要关联订单和原料，不强制创建染色缸批、染色配方或染化料领料单。染色配方采用发生在染色备料和执行前；不要求所有首工序都先完成染化料称量。

### 2.2 生产主链

```text
坯纱/坯布/半成品实际领用
 → 按路线选择松筒或其他前置准备
 → GX03 装缸
 → 配方采用、按阶段称料领料 → GX07 染色
 → 按路线选择独立漂洗
 → GX04 脱水
 → 按路线选择 GX05/GX06 烘干
 → GX08 络筒及对应紧筒排单
 → 按路线选择翻松、加网花灰、合股、加捻等
 → 检验/处置/放行
 → GX98 包装、细码与标签
 → 生产完成
 → 成品入库
 → 装车/出库、送货及交付
```

这是高频染色路线的业务展开。每张工卡使用其实际路线版本，独立松筒、加捻及其他产品分支使用各自节点。主料领用、染化料按阶段领用、质量检验与包装记录各自关联生产对象。

过程检验可以在装缸、染色或其他执行节点发生，不必等到末端。未通过检验时进入隔离、返修、复检或其他具体处置；复检放行后再继续相应生产、包装或交付动作。

具体处理：

5. GX98 有大量计划，WProcess 没有对应记录，包装事实候选在 RecordYield、相关打包与细码入口。包装完成动作推进对应计划节点，不能要求先补一条普通刷卡实绩才能入库。
6. 同一计划节点允许多轮实际执行；多次 GX07 记录需要区分刷卡、补录、复染及返修来源，不能统一累加成重复产量。

8. 工序转序不自动生成仓储入出库。只有实际入仓、出仓、换库位或登记投入/产出的业务动作才形成相应库存事实。

### 5.3 C 批：采购、来料、批次及仓储基本动作

采购模型：`PurchaseRequest`、`PurchaseRequestLine`、`PurchaseOrder`、`PurchaseOrderLine`、`PurchaseReturn`、`PurchaseReturnLine`。

仓储模型：`InventoryLot`、`StockReceipt`、`StockReceiptLine`、`StockIssue`、`StockIssueLine`、`InventoryMovement`、`StockBalance`、`StockTransfer`、`StockTransferLine`、`StockCount`、`StockCountLine`、`StockAdjustment`、`StockAdjustmentLine`。

- 正常采购：申请/订单→确认→到货与供应商原批号→来料检查→分批入库；入库明细关联采购明细。采购进度按有效收退量汇总，采购单数量不直接生成库存。
- 无采购单的零星采购保留明确入库类型、供应商和批准事实；客供来料记录客户货权，不强行关联一张虚构采购单。超收、容差及旧审批规则按照第 9 节处理。
- 批次明确物料、所有者和来源批号；自有库存也有真实所有者。不同货权和质量状态分别查询；采购退货引用原收货，通过实际出库处理。
- 入库确认和生效分别记录；出库的领用用途在 D/E/F 接入后关联对应业务对象。生效在同一事务写来源状态、流水和余额，重复生效不增加第二份库存。
- 余额按“批次＋实际库位＋质量状态＋可选包装单元”核对，只由流水形成。物料基本单位是实际库存单位，辅助重量和粒数分别保存。
- 冲销追加原流水同维度的等量反向记录；已被下游领用或转化的来源先处理对应下游。当前余额非负是现有新模型规则，历史负数记录按真实逆向来源归类，不自动改为正数。
- 调拨产生源库位与目标库位的成对流水。盘点保存开始时账面快照，区分未盘与实盘零；盘点差异通过调整单生效。第一版按明确盘点范围冻结收发，属于本项目拟定作业方式。
- 来料质量记录发生在有工卡之前，现有检验模型尚不能完整表达；采用第 8 节的补项。来料检查通过前的数量可登记为待检库存，是否入仓按实际来料操作；可用库存与待检数量分开。

库存事务与并发在正式业务数据库上验收。使用 PostgreSQL 的行锁：先锁来源单据和涉及批次，多批次按固定顺序，再读取和更新余额；首笔收货也先锁已有批次对象。当前 SQLite 可继续开发页面和普通逻辑，其验证不能证明多人并发扣库正确。具体数据库准备承接现有框架方案，执行时单独迁移和核对本项目数据。

C 验收：采购分批收退、客供来料与自有料、待检及可用数量、调拨、盘点调整和冲销均能对账；并发领用不能超出同维度余额；失败事务不留下部分流水。

### 5.4 D 批：工卡、数量分配、拆合缸与排程

接入 `WorkCard`、`WorkCardOrderAllocation`、`DyeBatch`、`DyeBatchWorkCard`、`DyeBatchAllocation`、`WorkCardOperation`、`OperationParameter`、`WorkCardRequirement`、`ScheduleAssignment`、`ProductionRecipe`、`MaterialPlanStage`、`MaterialPlanLine`。

1. 从有效订单行或明确授权来源创建工卡，保存规格、色号、数量单位、实际路线版本及要求快照。工卡与订单的数量分配通过已有分配表保存。
2. 支持一个订单行拆多张工卡、多工卡按明确工艺组合为缸批。缸批成员与对应订单分配均保存数量；取消或重分配保留原采用事实，已执行部分不能直接移到另一缸批。
3. 染色任务组缸后选采用配方，保存阶段、原料、剂量、干料计算基准、浴液数据及计划量。新业务明示干料百分比或 g/L 基准，历史 0/1 的百分数含义按已核实口径处理。
4. 按工序/机台适用关系排装缸、染色、紧筒等任务。先实现人工排程、插单、取消紧筒排单与重排；自动优化排程以后按真实需求增加。重排使旧安排被替换并保留版本。
5. 同缸成员共用物理染色时段，占用按该缸批统一计算；不能把同缸多张工卡判为彼此抢占机台，也不能因此放行不同缸批同时占用。
6. 跨工序机台采用对应节点；已核实的可承重量使用 kg，最低水位等单位未明确数据不进入容量计算。非染色路线不强制经过缸批和配方采用。
7. 路线前置检查来自已选择节点，返修单下达独立返修路线或新执行轮次。标准路线模板不为一次返修形成自循环。

D 验收：一订单多卡、多订单合缸、独立松筒/加捻都能排程；改排、拆合缸及配方替换可以查回原记录；生产采用数据不会随主档后续修改变化。

### 5.5 E 批：实际生产、称领退料、质量和返修

生产模型：`OperationExecution`、`ExecutionWorker`、`ExecutionMeasurement`、`ExecutionCorrection`、`WeighingOrder`、`WeighingStage`、`WeighingLine`、`WeighingRecord`、`ReworkOrder`。质量模型：`QualityInspection`、`InspectionResultLine`、`QualityDisposition`、`QualityDefect`；其他原表家族按本轮清单补完整办理。

仓储模型：`LotTransformation`、`LotTransformationLine`；实际领退料复用 C 的库存单据。

**开完工。** 员工/工卡识别→选择本次节点和机台→开工→人员参与与测量→完工。操作人员、班次、投入产出和时间保存到本次执行。工卡条码是对象识别，人员 RFID 是人员识别，扫描动作不直接等于某工序完成。重复扫描按已识别业务动作处理，不重复生成执行。跨日时间正常保存。

**称料及阶段领用。** 采用配方→计划阶段/物料→正常料单→实际称量→复核→具体染化料批次出库。染中加料、后处理料单、洗缸料单分别使用已定义类型和来源轮次，不覆盖正常计划。多笔称量与多笔领出分别汇总，余料退回引用原出库行；替料涉及采用变更与实际领退，不能只改物料名称。

**数量来源。** 人工实测与秤采集保存各自来源和实际时间。旧 NeedQty、RealQty、出库量分别保留；旧自动出库可能使用计划量，不能回填到实称。现有 `MeasurementSource` 只有 manual/scale，计划量兜底及更正来源等尚需补项；首期人工实际出库采用真实录入量，不生成假称量记录。

**转化与在制。** 通过转化投入/产出明细保存来源批次到半成品、成品批次的关系，关联实际领用和产出入库。车间工序完工只推进执行状态；需要独立半成品入仓时才生成半成品产出入库，下次领用引用该批次。

**质量与返修。** 对色、过程检验、包装前终检、缺陷、放行、让步、隔离、降级、返修、报废都在本批。检验结果与处置分开。返修流程为不合格→处置→返修任务及路线→必要加料/执行→复检→新的放行判定；原工卡、原执行和原检验保持可追溯。质量状态改变走明确库存调整/转换动作，报废是实物出库。

**报工更正。** 工序刷卡产量调整同步完成，使用 `ExecutionCorrection` 记录原执行、修改项、原后事实及原因。区分“不改”与“清空”；后续工序汇总和已生成的库存业务按实际影响更新或走逆向动作，不覆盖原执行记录。

包装前质量放行是当前资料建议的新业务默认流程；历史质量入口使用较少不能证明旧现场没有检验。旧 Q1～Q15、T1～T5 项目及单位未核实时不生成虚构检验标准。

E 验收：正常生产、染中加料、后处理、退料、跨日执行、报工更正、不合格返修和复检均可走通。允许多轮执行但不重复累计同一实物产出，投入批次到产出批次有来源。

### 5.6 F 批：包装、成品入库、交付和客户逆向

仓储模型：`Package`、`PackageOrderAllocation`、`LabelPrint`。销售模型：`Delivery`、`DeliveryLine`、`SalesReturn`、`SalesReturnLine`、`CustomerComplaint`、`CustomerComplaintLine`。

- 包装前必经生产节点完成、对应数量获放行后，录入包装单元、毛重皮重净重、筒管及袋箱规格、订单分配、细码和标签。先创建尚未入库的产出批次身份供包装引用；批次身份存在不会增加库存。
- 包装净重采用显式方法：实称毛重扣筒管和外包装皮重，或已确认的固定单粒质量。包装完成保存采用方法和快照；附加重量未经核实不加入公式，粒数允许保留旧来源小数精度。
- 包装完成推进对应 GX98 节点；全部选定必经节点完成后记录生产完成时间。检验放行、包装完成、生产完成、正式入库和结案各有自己的时间及事实。
- 标签打印/重打关联同一包装单元；重打不增加包装或库存。打印请求和打印成功分别处理，现有打印模型不足部分见第 8 节。
- 成品入库明细关联包装、工卡、批次、库位和放行状态，通过 C 的生效服务记账。分批入库累计不超过对应完成且可入库的包装实物；“包装数量＝入库数量”在同一已入库范围内核对，不要求未入库包装提前增加库存。
- 选实际成品批次、包装及订单行建立送货，按装车明细组织所选实物；出库明细的 `delivery_line`、`package`、`lot` 保留正式关联。出库后再记录实际交付时间，不能把创建送货单当作已交付。
- 客户退回引用原交付、包装和出库来源，退回待检入库→检验处置→再放行/返修/报废。是否重新打开订单需求按明确处理意见记录。客户投诉可以无实物退回，问题、关联来源、处理和关闭分别记录。

F 验收：新色与老色订单、自有料与客供料、独立松筒/加捻、一单多缸、合缸、分批入库交付、退回返修都能正反向追踪。条码能查到包装、订单、工卡、配方及原料批次；交付数量和有效出库分别核对。

### 5.7 G 批：查询与设备按实际需要接入

业务查询随各批提供，G 批完成跨模块汇总：报价与订单价格来源、订单交期/分配/已投产/交付进度、来样确板、机台排程、工卡在制、计划与实耗、半成品流转、缺陷返修、包装细码、批次库存与收发流水。

每个报表明确时间、状态、货权、数量单位、逆向记录和数据来源。订单量、投入量、工序产量、包装净重、交付量不通过一个“数量”相互覆盖；不同物料或不同维度不能直接相加。

设备盘点从 A 开始；实际接入跟随对应业务：E 的扫码报工与称料、F 的秤和标签可在业务服务完成后逐项接入。普通人工版本先验收，不将资料包的全部设备网关、仪表或控制命令要求设为所有业务开发的前置。

| 接入项 | 资料包结论 | 后续处理 |
| --- | --- | --- |
| 员工/工卡扫码 | 人工触发报工明确存在 | 复用已实现开完工和更正动作，识别后由服务保存 |
| 包装电子秤/打印 | 入口在用，自动取值及打印回执未充分证明 | 根据实际设备协议接入；保留人工实测与人工打印确认来源 |
| WeighingSystem | 自动出库存在，计划量兜底与实称口径混合 | 按明确外部记录关联称量/出库，对账后采用实际来源 |
| KPS、旧 TF_METER | 有历史接口证据，当前使用不充分 | 先核实在用情况，启用项再设计任务与结果对应 |
| CCS | 任务下发及状态回传程序存在，当前入口不充分 | 单独记录任务、回传状态和 ERP 执行，按实际在用范围接入 |
| PDA、能源系统 | PDA 历史表为空；能源事实来源多种 | 移动作业按需求安排；能源与财务成本不进入本期基础闭环 |

资料包设备 P0/P1 是建设建议。正式接入某个设备时，再按该接口的重复、断线、回传、单位及业务采用场景验收；不为尚未启用的设备创建通用兼容层或模拟运行事实。用户此前说明的后台任务、签名密钥不列为本轮开发整改项。

## 6. 动作、状态与实际模型的对应

资料包03/06状态机包含目标设计，不是已核实的旧系统全部状态值。下表是既有业务枚举，需逐类核对旧行为。用户要求的草稿、确认、审核是明确的新系统办理要求，归一化单据尚未全部统一具备，需要补齐；审批事实与下表业务进度、旧原状态分别表达，不以一个字段覆盖全部含义。

| 对象 | 当前模型状态/事实 | 业务动作与前置顺序 |
| --- | --- | --- |
| 报价/确价 | `ApprovalStatus: draft→confirmed`；明细版本、有效期及确认标志 | 维护→确认采用；变价形成新版本，不以价格正数推断确认 |
| 销售订单 | `draft→confirmed→running→completed→closed` | 确认冻结需求/价格；实际执行后进入执行中；完成与结案分别操作；取消保留来源 |
| 打样任务/明细 | 任务 received/assigned/running/sent/confirmed；明细 accepted/rejected | 收样、分配、试验、送版、客户回复分别记录，确板指向试验和版本 |
| 配方/路线/曲线版本 | `draft→approved→active→retired` | 审核可用版本；采用后子明细一起冻结，历史引用不受停用后新版本影响 |
| 采购单 | `draft→confirmed→partial_received→received→closed` | 确认、分批收货、按有效收退汇总、结案；采购退货与原收货量核对 |
| 工卡 | `draft→released→running→completed→closed` | 下达、首选生产节点开工、全部选定必经节点完成、结案；completed_at 与 closed_at 独立 |
| 缸批 | `planned→scheduled→running→completed→closed` | 组缸、排程、实际执行、生产完成、结案；不代替工卡/包装/库存状态 |
| 排程 | planned/released/replaced/cancelled | 发布安排；改排使原版被替换，不覆盖已执行安排 |
| 工序执行 | `planned→running→completed` | 开工与完工属于本轮执行；更正追加记录，返修新增执行 |
| 料单 | `draft→confirmed→partial_issued→issued→closed` | 计划确认、实称/实际量复核、分批出库、结束；领出不等于自动拥有实称记录 |
| 检验/处置 | 检验 pending/pass/fail；处置 release/concession/rework 等 | 待检由检验和进度查询表达；工卡不需要冒充已有“待检”枚举 |
| 包装 | `draft→packed→received→issued`；returned/void | 包装完成、实际入库、实际出库、退回分别推进；条码重打不重建包装 |
| 库存单据 | `draft→confirmed→posted`；reversed/cancelled | 生效才改实物账；冲销关联原流水；确认可与生效同次执行但事实含义分开 |
| 交付 | `draft→confirmed→issued→delivered` | 来源/价格确认、实际出库、客户交付；本期终止于交付与业务结案 |

“已提交”在当前订单业务状态中不存在，旧入口如有该事实则补明确对应；“信用审核”涉及独立财务规则，不自行设成全部业务的强制前置。确认与审核按用户要求分别记录，不再用当前确认动作冒充全部审核事实。

所有关键动作的定义包含：来源对象与明细、允许当前状态、本次数量单位、操作者与时间、采用快照、下游变化、对应逆向动作。动作在服务端按已知规则实现，前端不直接写状态。

## 7. 写入、计算和页面实施约定

### 7.1 实际业务服务

在现有七个应用内按需要补services、serializers、views、urls。普通查询复用框架；确认审核、下达工卡、配方采用、开完工、放行、库存生效和冲销使用明确动作接口。单据主从表一次提交，业务编排与事务由服务负责，接口负责参数和权限。

- 明确写入入口调用 `full_clean()`；组合保存后核对主从表及跨单据分配，不依赖普通 `save()` 自动调用校验。
- 关键数量分配、出库、入库与状态一起提交。重复库存生效、重复执行请求的处理依据实际来源和动作身份，不给所有基础资料额外套统一重试流程。
- 版本采用冻结阶段、染化料、路线节点和曲线等完整内容；后续修改保存新版本。快照使用已知字段，不能读取实时主档替代历史。
- 编号规则逐类按最新有效入口整理，编号在对应保存动作产生；名称、日期、旧明细号不能代替真实关联。
- 使用已有账号、菜单、角色、按钮及数据范围。查看、草稿编辑、确认、放行、冲销、更正、重打、结案与导出按岗位授权。
- 普通主数据使用通用列表和表单；单据使用主从编辑、来源选择、进度和动作区域。复用 ResourceTable、RemoteSelect、TableSelect、FilePicker 与 `web/src/api.ts`，关联选择显示单号、规格、颜色和来源状态。
- Decimal 以字符串传输，计算在后端明确单位与精度；页面预览和正式确认快照各有用途。

### 7.2 计算采用时点

| 口径 | 计算与采用 | 后续动作 |
| --- | --- | --- |
| 订单数量分配 | 同一来源、同维度换算后核对工卡/缸批/订单行分配 | 分配变更重新核对已执行部分，不从计划量推断实绩 |
| 百分数用量 | 明确干料 kg × 剂量百分数 ÷ 100 | 采用时保存基准、剂量及计划量；旧百分数未证明干料基准的保留原口径 |
| g/L 用量 | 明确浴液 L × 剂量 g/L，换为库存基本单位 | 保存浴液事实；质量浴比转体积需要实际密度依据 |
| 计划调整 | 保存原剂量、调整百分比及最终采用量 | 加料和换版保留轮次，不覆盖已称已领原量 |
| 实称/领出 | 分别汇总称量记录及有效出库，退回引用原出库 | 差异显示计划、实测、净领用，不相互补填 |
| 工序时间 | 根据实际本轮及已确认更正显示经过时间 | 刷卡时长不自动成为机器运行工时或工资工时 |
| 包装净重 | 明确毛重−单筒皮重×粒数−外包装总皮重，或确认固定粒重×粒数 | 包装完成保存方法与采用量；附加重量待核实 |
| 库存/盘点 | 有效流水汇总余额；实盘−盘点账面快照形成差异 | 调整/冲销通过相应来源，不能直接改余额 |
| 交付进度 | 按有效交付及实际出库、退回分别核对 | 业务完成与结案按需求完成及实际处置决定 |

缺少计算所需事实时保持未计算，明确具体缺项；不能填零、计划替实称、英文名猜含义或切换到另一公式。

### 7.3 不做防御性编程

按已经确定的模型和字段直接访问，业务服务实现本项真实状态、数量、来源及权限规则。异常直接返回可定位的原因。

不增加猜字段名、多个旧名兼容、广泛捕获后吞异常、失败后返回空列表/零、虚构默认对象、万能适配器或为不存在的场景增加备用路径。业务所需的事务、库存不足判断、版本冻结、返修与冲销按实际动作实现，不扩展成额外的通用防护框架。

## 11. 数据导入、原键字段与试运行

### 11.1 导入次序

1. 通用字典→组织→员工班次→仓储层级→单位→主体与角色→物料规格→机台工序适用→路线版本→色号样品；按实际外键微调建档先后。
2. 配方、曲线与确板记录按真实依赖导入：先建立可独立配方身份和版本，再导入引用版本的试验/确板记录；有引用环的按明确映射补关联。随后导入报价/确价版本。
3. 销售/采购及变更、真实来料批次与收发来源→工卡及数量分配→缸批与排程/采用快照→称量/执行/质量及返修→包装→实际成品入库/出库交付→退回及其他逆向。
4. 第 3 步是来源对象建立顺序；存在循环外键时按明确来源映射分两步建独立对象、补真实关系，库存生效时间仍按实际有效事件。不能因导入排序而改旧业务日期。
5. 迁移切换的期初库存与历史重建流水分别确定范围；同一库存不得用完整历史和切换期初重复建立。

### 11.2 原键字段和比对

全部现有 ERP 模型取消额外旧 ID 列。原表模型保留原主键全部字段及来源批次/提取行；已转换主档使用既有来源映射。联合键保留全部列、前导零及原值；派生对象通过办理上下文保留全部直接来源，不任选一条代表多条。

每批记录来源文件/抽取时间、行数、哈希、字段/单位/状态转换、来源主键与新对象映射、未导入项和原因。逐行对照原键字段及来源信息及主要事实，分货权、物料、仓库、批次、单位核对有效数量与关系，不能只比较总行数。

已新增完整旧来源、原主键与逐字段对照页面，以及明确主档导入管理命令。完整历史归档和规范化业务采用分别记录；复杂业务导入使用对应导入服务，不直接套通用 Excel 导入。

### 11.3 已知历史问题

工卡旧重量单位及缸号为空、合卡孤儿、实称大量为空、粒数小数或负数、重复包装条码、质量槽位和附加重量含义等继续按字段差异说明处理。新增识别的刷卡时间逆序/短时记录也保留来源，不能改造成正常连续工时。

旧来源身份与业务数量、时间分别核对；SQL别名、派生展示字段与固定空占位不额外导成独立业务事实。历史未满足新动作所需事实的记录仍完整承接到对应业务模型和查询，保存原字段、原状态及未解析关系；原始归档另作核对证据，不调用新动作制造从未发生的生产、放行或库存。

### 11.4 试运行样本
