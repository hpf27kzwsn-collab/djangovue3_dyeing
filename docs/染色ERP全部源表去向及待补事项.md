# 旧ERP全部源表去向及待补事项

采集结构 690 张表、13268 个字段；每张表均有登记。

553 张基础/业务表已生成模块内静态模型，含公司抬头、编号规则、审批配置/事实/待办、业务字段变更和提交通知规则等14张带平台前缀的业务支撑表。质量责任及扣奖明细WDefectPenalty也完整建模，不因包含金额而排除业务数量和责任事实。47 张独立财务/工资核算表按此前财务暂不实施的范围列出；90 张其余平台配置、权限、日志表保留结构证据，供现有平台及业务映射。下表明确列出每张表，平台分类仍应结合用途核实；如发现其中业务实体，必须补成业务模型。没有因空表、停用、低频或异常而删除业务表。

当前已有完整原行快照覆盖 91 张表，共 9,055,094 行；其余基础/业务表的当前原行需要继续只读抽取。当前 SQL Server 服务停止，因此本轮使用 2026-10-12 结构证据；待重新可连接后比较结构变更，再追加迁移。这是来源采集待办，不是放弃复刻清单。

## 尚待完成的工作

1. 继续只读采集未覆盖源表和原界面/存储过程的业务联动证据。
2. 按每张原表的真实计算、提交、反审及逆向操作完善业务动作。当前原表模型提供字段录入与办理阶段，不据此宣称原库存、采购、工艺等联动已全部还原。
3. 在试导入库分批导入全部原行，逐字段和主从对照，保留原状态、原码、重复记录；不筛掉异常。
4. 明确同一组织、单位、责任工序的业务配置，采用用户已填答案；只对证据仍不能确定的具体事项提问。
5. 历史导入不重演库存过账，不将全量历史与切换期初再次叠加。真实设备接入另按连接资料实施。
