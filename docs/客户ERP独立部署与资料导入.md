# 染色ERP独立运行与资料导入

本系统使用客户自己的数据库。客户自行导入资料、录入单据；运行不需要旧ERP、旧SQL Server或任何开发导出文件。

## 安装运行

运行目录包含`backend`、`web/dist`和数据库配置示例。准备Python和PostgreSQL，创建客户自己的空数据库及账号。

系统实时消息和异步导出使用Redis。启用时设置本部署的`REDIS_URL`，异步导出还需在`backend`启动`python -m celery -A application worker --pool=solo`。它们使用本系统的数据，不需要旧ERP服务；普通单据同步保存、导入和查询使用本地数据库。

1. 将`database.ini.example`复制为同目录的`database.ini`，填写新数据库名称、账号、密码、地址和端口。
2. 在运行目录安装后端依赖：`python -m pip install -r backend/requirements.txt`。
3. 设置`DJANGO_DEBUG=0`和本部署自己的`DJANGO_SECRET_KEY`；按访问地址设置`DJANGO_ALLOWED_HOSTS`。后端默认监听本机，客户局域网部署时按实际服务器地址配置。
4. 在运行目录执行`python backend/manage.py migrate --noinput`、`python backend/manage.py init_data`、`python backend/manage.py collectstatic --noinput`。初始化只建立系统配置和岗位，不导入客户、物料、报价或历史业务单据。
5. 进入`backend`，执行`python -m uvicorn application.asgi:application --host 127.0.0.1 --port 8001`，浏览器打开`http://127.0.0.1:8001/`。前端由同一后端提供，无需客户运行Node开发服务器。

首次管理员为`superadmin`，初始密码`admin123456`，首次登录后修改密码。账号、岗位、权限和编号规则在系统管理维护。业务资料在对应业务模块维护。

## 导入和录单

先导入部门、员工、客户/供应商、物料、单位、仓库/库位、机台/工序等实际需要的基础资料，再导入报价、工艺和路线等业务资料。每类资料使用对应入口和模板；不需要的类别可之后补充。

- **普通新增导入**：与页面新增使用同一保存、编号和联动规则。
- **原值导入**：保留上传文件中的字段，不重新编号，不重演历史库存和生产事件。既有标为“历史基础资料原值承接”的模板继续兼容。文件不需要旧数据库连接或旧库快照。
- 相同名称或重复来源逐行保留。只有本地关联唯一明确时自动关联；多候选保留原编码，由对应业务入口明确选择。
- 编号是否自动生成、能否手填/修改，由编号管理中对应模型及类别的规则决定。未配置的编号按入口实际要求填写。
- 导入失败显示文件行和字段；不会把错误行悄悄跳过。导入结果及批次记录可在系统管理查看。

质量统计数量在质量管理中按“数量集”和“统计数量明细”维护，可自行录入或从对应入口导入Excel；无需旧库抽取文件。数量、长度、单位及日期可按实际保留空值，重复行不会自动合并。关联列可选模板中的“名称 [ID]”或明确填写本地记录ID，未知ID会报告具体行错误。

单据审核及反审使用本身的业务状态，没有额外通用确认阶段；真实业务中的打样确认、设备维修确认等仍按对应业务办理。

订单选择的是本地客户、本地物料及本地报价；后续开卡、工艺、排产、报工、质量、包装和收发引用同一套本地记录。扫码识别返回所有匹配记录，选择实际要办理的一条；识别本身不生成报工或库存。

财务、打印及已登记暂缓查询不在当前启用范围。实际现场设备需按其协议接入新系统；部署不从旧数据库获取刷卡数据。

本次独立运行验证不等于客户现场验收。正式导入及启用由使用人操作，开发测试资料不会随运行包附带。
