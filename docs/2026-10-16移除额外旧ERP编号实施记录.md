# 移除额外旧 ERP 编号实施记录

本次执行用户确认的来源方案：删除所有模型额外添加的【旧erpID】，保留旧表原键及全部原字段；导入、对比、历史识别和后续方案同步更新。

## 已实施内容

- 700 个当前 ERP 模型取消公共 `legacy_id`；质量数量投影取消 `header_legacy_id`。数据库共删除 701 列。
- 589 个原表模型的 12,016 个原字段保留，原主键、联合键各列、原自增值、原状态和计算结果不因本次调整改变。
- 原表导入使用已有来源批次/提取行；逐字段比较直接比较原字段，不再生成或比较额外 JSON ID。没有可靠键及重复原键的行分别保存。
- 通用主档导入先承接原形记录，再依据现有 LegacyObjectMap 采用主档。无键、重复原键、字段转换不兼容、多来源目标及历史值改变均保留原形记录并登记原因。输出分别统计原行承接、主档采用、仅原形承接及本期排除的财务字典数量。
- 历史识别采用来源批次。工位归档副本通过已有归档上下文识别历史来源，保持批次/提取行为空，避免混入原抽取行集合。
- 业务查询、导出、选择器和报表改为使用原字段及直接来源；页面、字段权限、模型生成器、导入命令及测试同步调整。
- 质量投影保留原明细号、明细中的表头流水，另从原 JSON 中迁出实际匹配的原表头流水 `header_sheet_series`；孤立明细不虚构匹配表头。字段原有权限随名称调整保留。
- 业务参数的原键是已有 `name`（原 ParamName）；来源表/架构和原字段名称迁入现有办理上下文。

## 数据库升级与备份

开发库：`erp_full_trial_20261014`。执行 9 个新迁移，将数据整理和删列拆成独立事务，避免 PostgreSQL 尚未结束的约束触发事件阻止同表结构修改。

删列前核验 700 张表，共 68,371,951 行；66,910,255 行包含待删除列的非空值。原表复刻记录未发现缺少来源批次而仅有额外 ID 的历史记录。另核对 1,343 条已转换主档、13 条业务参数及 401 条质量数量来源。

备份目录：[data-backups/remove-old-id-20261016](../data-backups/remove-old-id-20261016)。包含 194 份按新系统内部 id 定位的删列前 CSV 压缩文件、全表行数、列定义及相关 701 个菜单字段/1,958 条权限记录；197 个备份文件登记 SHA256。备份保留在本机，不纳入 Git。

回退结构迁移只能恢复空列，不能恢复已删值。需要恢复时，按照备份中的列定义及内部 id 回填原值，并恢复对应菜单字段及权限；完整来源文件仍保留。不能把重新加列误称为完成数据恢复。

## 已完成的数据核验

迁移后全部 700 张表数量核对通过。原有行保留，只有来源上下文增加 13 行，合计 68,371,964 行。其他 ERP 表数量不变，旧键字段未删除。

6 张实际来源表完整逐字段比较通过：客户 182 行、字段选项 827 行、班次 33 行、查询枚举 403 行、流程步骤 16 行、细码拆合日志 173 行；共 1,634 行、38,573 次原字段比较。

401 条质量数量来源逐行核对原明细号和实际匹配表头流水通过；原表头字段的权限设置保留。当前库不存在 `legacy_id` 或 `header_legacy_id` 数据库列，ERP 菜单字段也不再引用它们。

实际客户、通用主档、质量数量列表和原表导出共 4 个接口检查通过。机器结果见 [数据升级核验记录](erp-source-provenance-verification-20261016.json)。全库数量核对与上述 6 表逐字段核对分别登记，不把数量核对写成全库逐字段重比。

## 规则及文档

当前规则见 [原键字段与来源追溯规范](原键字段与来源追溯规范.md)。后续开发方案、七模块模型优先方案、原字段清单、字段差异说明、剩余工作盘点及异常说明已同步调整。早期实施记录和验证 JSON 保留当时事实，并注明旧 ID 方案已经被替代；旧迁移定义保留用于数据库历史重建。

财务系统继续暂不开发。异常、孤立关联、NULL、负数、重复条码及完全重复原行不因本次调整被跳过。

## 最终验证结果

- 当前开发库执行全部 9 个新迁移成功；上述 700 表数量、401 条质量原键、字段权限、6 表逐字段对比和 4 个实际接口核验通过。
- 最终 9 迁移链从空库完整安装通过；从旧结构带数据升级通过，覆盖重复原行、已采用主档映射、参数来源、匹配及孤立质量明细和字段权限。
- 后端全范围回归执行 749 项，其中 745 项通过，4 项报错：一整个测试模块仍引用已删除的旧 ID 构造函数，以及三处测试仍使用旧字段格式或不完整的原表必填值。修正后补跑相关 29 项全部通过，包括此前未加载模块的 12 项；同时核对当前完整测试发现数为 760 项。全范围运行与修正复测合计覆盖全部 760 项，不将其表述为一次全绿的完整运行。
- 最终导入测试 6 项、包装与染程等报表测试 64 项、跨卡及采购质量等来源关联测试 102 项均通过；原键和逐字段对比 7 项通过，并纳入上述 29 项再次通过。这些复测与完整回归重叠，不重复累计测试数量。
- Django 系统检查通过，迁移一致性检查为 `No changes detected`，前端类型检查及正式构建通过，Git 差异格式检查通过。前端仅保留原有构建分块大小提示。

测试过程中发现的旧断言已经修订为验证实际原键类型、来源批次及精确原行关联；没有通过放宽业务断言、吞掉异常或过滤重复记录来使测试通过。本次没有新增需要现场确认的业务复刻异常。
