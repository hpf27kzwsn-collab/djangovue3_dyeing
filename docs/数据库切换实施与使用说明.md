# 数据库切换实施与使用说明

## 当前方式（2026-10-11）

用户不需要桌面打包，packaging 和 PyQt/PyInstaller 专用依赖已经移除。当前通过源码脚本或项目根目录 database.ini 选择数据库；以下历史记录里的 Windows 设置窗口、exe、旧包目录已不再使用。

默认 SQLite，固定 Python 3.14.8 / Django 5.2.18，PostgreSQL 使用 psycopg/binary 3.3.6。无需生成 exe；PostgreSQL 服务器仍需已安装并运行或使用现有远程服务器。

以下命令在项目根目录执行，密码隐藏输入：

```powershell
# 查看目标，不显示密码
.\.venv\Scripts\python.exe scripts\database.py show
# 使用已有账号/数据库
.\.venv\Scripts\python.exe scripts\database.py postgresql --host 127.0.0.1 --port 5432 --name djangovue3 --user djangovue3
# 首次创建应用账号和空数据库，需要服务器管理员
.\.venv\Scripts\python.exe scripts\database.py postgresql --create-database --admin-user postgres
# 初始化全新数据库；已有数据搬迁不能用它代替
.\.venv\Scripts\python.exe scripts\database.py initialize
# 切回 SQLite
.\.venv\Scripts\python.exe scripts\database.py sqlite --path db.sqlite3
```

也可复制 database.ini.example 为 database.ini 直接填写。配置文件位于项目根目录，SQLite 相对路径从 backend 起算；进程环境变量优先于 INI，`.env.example` 不自动加载。网页、worker、beat 修改配置后全部重启。

切换配置不搬迁数据。要保留数据，先让在途任务结束并停写，准备源/目标两个 INI，使用相同代码和插件迁移版本，搬迁到空目标：

```powershell
.\.venv\Scripts\python.exe backend\manage.py transfer_database --source-config source.database.ini --target-config target.database.ini
```

SQLite 源建议填绝对路径；目标 PostgreSQL 空库先建账号/库，不先执行 init_data。反向搬迁使用新的空 SQLite 文件。附件留在 backend/media，复制到另一目录或电脑时单独保留；Redis 队列不由该命令搬迁。

原正式 SQLite 和3附件现已接回源码 backend，所有账号/授权/业务数据保留。旧包数据库与附件去重保存在 data-backups/source-only-20261011，映射见该目录 data-index.json，原开发数据位于 previous-source-data。旧包二进制与构建产物已删除。

取消打包后107项源码测试和25资源接口通过，数据库切换实现保持；此前 PostgreSQL 双向搬迁和真实任务结果仍是有效历史证据。本次源码启动按实际时间执行到期 celery.backend_cleanup，调度计数/时间戳和清理任务结果发生正常运行更新，未假称运行后所有表逐字不变。

实施日期：2026-10-10。固定 Python 3.14.8、Django 5.2.18；默认 SQLite，新增 PostgreSQL。本次不引入 MySQL、多租户或 ERP 业务模块。正式程序继续使用原 SQLite 库。

## 1. 实现内容

| 项目 | 实现 |
| --- | --- |
| 共用配置 | `backend/application/database_config.py`，源码、管理命令和 Windows 包共用 |
| 默认数据库 | 未配置时使用自身 `backend/db.sqlite3`，保留原 SQLite 事务设置 |
| PostgreSQL | Django 官方 PostgreSQL 后端，psycopg/binary 3.3.6；不添加连接池或业务重试 |
| 配置入口 | Windows 启动器“数据库设置”；源码版 `scripts/database.py`；可直接编辑外部 INI |
| 连接/建库 | 测试实际连接；使用管理员创建应用账号和数据库，不自动安装服务器 |
| 初始化 | 对所选数据库执行迁移、菜单/权限/区域初始化；Windows 同时收集静态文件 |
| 数据搬迁 | 独立 `transfer_database` 命令，SQLite/PostgreSQL 双向复制到空目标库 |
| 数据库状态 | `/readiness` 显示实际 `sqlite` 或 `postgresql` |
| 适配修正 | 列表预取按数据库实际参数能力分批；PostgreSQL 无参数上限时正常运行 |

Windows 启动器先显示窗口，再以子进程初始化数据库，成功后启动网页、worker、beat 等服务。连接/初始化失败时保留窗口和日志，能够重新打开数据库设置；不会偷偷改回 SQLite。

## 2. Windows 程序如何切换

1. PostgreSQL 服务器须已安装并启动，或已有可连接的远程服务器。应用只打包数据库驱动，不打包/安装数据库服务器。本机已有 PostgreSQL 18.6 服务；本次未改其原库、账号或服务设置。
2. 如需保留数据，先按第 5 节完成离线搬迁；如使用全新数据库，则可直接初始化。
3. 在启动器点击“数据库设置”，选择 PostgreSQL，填写服务器、端口、数据库、账号、密码及 SSL 模式。
4. 已有账号/库时点击“测试 PostgreSQL 连接”。尚未建库时点击“创建 PostgreSQL 账号和数据库”，输入服务器管理员账号及密码。
5. 保存配置。启动器会重启其管理的服务，对目标库初始化后启动。新库有独立初始账号；搬迁库保留原账号、密码和改密计数。

建库工具给新应用账号登录及数据库所有者身份，不给服务器超级管理员权限。已有同名账号不会被改密码；已有库不会被清空。管理员密码仅用于当次建库，不保存；应用密码保存于 INI 文件，窗口中隐藏显示。

切回 SQLite 时选择 SQLite，填回原文件路径并保存。原 SQLite 文件仍保留；切换期间在 PostgreSQL 新写的数据不会自动回到 SQLite，需要反向搬迁。

数据库配置是整个应用实例的运行配置，不放进网页“系统配置”中；网页自身需要先连接数据库才能工作。

## 3. 配置文件与优先顺序

源码默认文件：项目根目录 `database.ini`。Windows 默认文件：`djangovue3.exe` 同目录的 `database.ini`。示例为项目根目录 `database.ini.example`，实际配置文件已加入忽略规则，不应随源码提交。

```ini
[database]
engine = postgresql

[sqlite]
path = db.sqlite3

[postgresql]
host = 127.0.0.1
port = 5432
name = djangovue3
user = djangovue3
password = 填写应用账号密码
sslmode = prefer
```

SQLite 的相对路径相对于实例的 `backend` 数据目录；不同位置的源码库和 Windows 库仍是不同数据库。外部 INI 可用 `DJANGO_DATABASE_CONFIG` 指定。配置不使用百分号插值，密码中的 `%` 原样保留。

优先级为：进程环境变量 → INI 对应字段 → SQLite/服务器等默认值。`.env.example` 仅说明变量，脚本不会自动加载。PostgreSQL 的库名、账号和密码须填写；选中 PostgreSQL 后配置或连接错误会直接报告，不回退另一库。

| 环境变量 | 用途 |
| --- | --- |
| `DJANGO_DATABASE_CONFIG` | 外部 INI 路径 |
| `DJANGO_DB_ENGINE` | `sqlite` / `postgresql` |
| `DJANGO_SQLITE_PATH` | SQLite 文件路径 |
| `DJANGO_DB_NAME` / `DJANGO_DB_USER` / `DJANGO_DB_PASSWORD` | PostgreSQL 数据库/账号/密码 |
| `DJANGO_DB_HOST` / `DJANGO_DB_PORT` / `DJANGO_DB_SSLMODE` | 服务器/端口/SSL 模式 |

若启动环境已指定数据库变量，修改 INI 不会覆盖那些变量，需同步修改启动环境。源码网页、worker 和 beat 必须读取同一配置；修改后重启三者。Redis 与附件目录不因数据库类型自动改变。

## 4. 源码版配置和初始化

以下命令在 `H:\Project_python\django-vue3-admin\djangovue3` 执行。密码使用隐藏输入，不放在命令参数中。

```powershell
# 已有应用账号和数据库
.\.venv\Scripts\python.exe scripts\database.py postgresql --host 127.0.0.1 --port 5432 --name djangovue3 --user djangovue3

# 尚未创建账号/数据库；需要服务器管理员的权限
.\.venv\Scripts\python.exe scripts\database.py postgresql --name djangovue3 --user djangovue3 --create-database --admin-user postgres

# 显示连接目标，不显示密码
.\.venv\Scripts\python.exe scripts\database.py show

# 初始化当前所选数据库，然后按 README 启动网页/任务服务
.\.venv\Scripts\python.exe scripts\database.py initialize

# 切回默认 SQLite
.\.venv\Scripts\python.exe scripts\database.py sqlite --path db.sqlite3
```

`initialize` 创建/升级表结构和初始化数据，不能代替搬迁已有业务数据。正式迁移目标须先搬迁再正常启动，避免先初始化产生种子数据而使目标不再为空。

## 5. 已有数据的离线搬迁

1. 先让在途任务完成，停止网页写入、worker 和 beat；保留源库及附件备份。消息队列仍存于 Redis，不在数据库搬迁范围内。源库和目标库须使用相同项目代码及插件迁移版本。
2. 准备两个独立配置文件，例如 `source.database.ini` 和 `target.database.ini`。SQLite 建议填写源文件的绝对路径；目标 PostgreSQL 使用已建的空库。反向搬迁使用新的空 SQLite 文件。
3. 执行以下命令。它读取两个明确的配置文件，忽略数据库环境变量对这两个目标的覆盖；不会修改当前 `database.ini`。

```powershell
# 源码版
.\.venv\Scripts\python.exe backend\manage.py transfer_database --source-config source.database.ini --target-config target.database.ini

# Windows 包版；从 exe 同目录执行
.\djangovue3.exe --manage transfer_database --source-config source.database.ini --target-config target.database.ini
```

4. 搬迁成功后通过配置入口选中目标，重新启动网页、worker、beat。保留源库用于回看。要反向复制，交换源/目标配置并使用空目标。

命令先对目标执行 Django 迁移，只允许写入无业务数据的目标。它不是已有两库的合并/增量同步工具：保留主键、关系、软删除数据、密码哈希、任务配置与结果、文件路径；ContentType/Permission 由目标迁移生成并通过自然键关联。导入重置自增序列，保留日期时间完整微秒；导入时暂时断开 beat 库会错误写默认库的相关接收器，保留源库内容及调度时间。

附件二进制文件不在数据库中。同一实例切换继续使用原 `backend/media`；搬到另一台电脑/目录时另行复制整个 media 目录。跨实例需要保持一致的签名密钥，才能继续使用原签名令牌；默认本地密钥设置本次没有改变。

数据库调度数据可以搬迁，但停机期间跨过执行时间的定时任务应按实际业务确认启用时间。本次不添加自动补跑、业务去重或“永不重复”的承诺。

## 7. 失败记录与实现取舍

早期 PostgreSQL 用例暴露了测试模型迁移顺序、测试客户端重复关闭流导致事务连接关闭、调度器测试使用不适合的回滚事务等问题，已修正测试安排并原用例重跑；没有删除断言或跳过失败用例。旧失败日志保留于 docs。

搬迁最初发现默认 JSON 时间格式截短微秒、beat 导入接收器可能写默认库；两者已经通过实际往返比较修正。测试 Redis 初次使用 Windows 绝对配置路径，而该社区发行按 Cygwin 路径解析，改为与现有程序相同的相对路径；这是验证脚本配置错误，未给产品添加启动重试。临时目录受沙箱限制的验证在正常本机权限下原样执行。

本次采用标准库 INI、Django 后端和独立离线搬迁，不增加自动回退、双写同步、额外业务字符/数量限制或未经需求指定的多租户模块。建库/搬迁中的必要目标判断用于完成其定义的操作；界面异常提示用于显示实际失败原因，不吞错冒充成功。详细选择追加于根目录《疑问与方案记录.md》。
