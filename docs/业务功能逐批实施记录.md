# 业务功能逐批实施记录

沿用《染色ERP后续开发方案》的 B～H 顺序。财务系统不在本期范围。旧系统只作为只读证据来源；新建业务记录与测试数据分别存放在项目数据库和独立测试数据库。

## B：价格、订单、打样与配方

已接入 17 个业务资源：商业价格及明细，订单、颜色规格与技术要求、订单变更及明细，来样通知及明细、试验轮次、送版确板，配方主体、版本、染程及物料，曲线版本及步骤。

页面支持表头和关联明细、分页关联选择、业务状态操作，以及一次提交本层表头和明细的整单编辑。保存失败时整单回滚；明细不能移到其他表头。业务办理和查询角色只在首次创建时授予初始权限，重复初始化保留用户已有授权。

| 对象 | 动作及约束 |
| --- | --- |
| 商业价格 | 草稿确认后冻结表头和明细，保留基础价、另计价、对客报价及总单价各自事实；未填写的组成价不补零 |
| 订单 | 价格来源核对客户、物料、色标准及有效期；没有来源的手工定价必须说明原因、单价和单位；确认后冻结 |
| 订单变更 | 对已确认或生产中的订单执行，保存原明细事实；新数量不得低于有效工卡分配量，不改已采用生产快照 |
| 打样 | 收样→分配→多轮试验→送版→客户回复；每次拒绝和下一轮试验独立保存；完成前不能送版，送版前不能确板 |
| 确板 | 接受时明确色标准、实际试验及已审核配方版本，并核对一致性；所有有效明细接受后主单已确板 |
| 配方/曲线 | 草稿→审核→启用→停用；冻结后通过复制生成新草稿，保留完整阶段及明细，复制不带旧系统id |

### 字段补项与合理处理

所有新增模型继续继承 `ErpModel`，包含额外字段“旧系统id”；普通业务接口不可填写或更改，由专用导入维护。

1. `SalesOrderLine.price_source`：明确采用的商业价格明细外键。
2. `SalesOrderLine.adopted_price_snapshot`：采用价格的精确快照，20 位、6 位小数。旧 `OrderColor.Price` 对应的 `unit_price` 仍为 8 位、2 位小数，不用舍入价格资料来适应旧字段；两个字段含义不同，交付按来源精确快照或明确手工价选用。
3. `SalesOrderLine.manual_price_reason`：手工定价原因。
4. `SalesOrderChangeLine.before_values`：实际确认变更时保存的原明细 JSON 事实。
5. 基础信息新增 `BusinessAction`：业务对象、对象 ID、动作、原因、操作前/后事实，继承操作者、部门和时间字段。普通接口只读，记录关键业务动作，不设置通用审批引擎。

上列是新系统补项，不冒称旧系统存在同名物理字段。旧系统原有字段的名称、精度、NULL 和原值仍按逐项对照保留。

## C：采购、批次库存及盘点

已接入采购申请、采购订单、采购退货及对应明细，以及 13 个仓储资源。采购确认冻结需求；实际分批收货和采购退货按明确单位换算更新采购进度。新来料先进入待检库存，由后续来料检验与处置放行；客供料货权与客户一致。

库存确认与过账分开。过账在同一事务内锁定来源单据、相关仓库、排序后的实物批次，更新准确维度的余额并写入流水。相同过账再次提交返回已经生效的单据，不新增流水；库存不足时整单回滚。余额和流水普通接口只读。余额首建同样保存操作者和部门。

调拨生成同一批次的发出与接收两条流水。冲销保留原流水并生成等量反向流水；同维度的后续有效业务必须先按逆序处理。盘点冻结整仓收发，生成账面快照，不删除快照行；未盘数量保持 NULL，实盘零形成完整短缺差异。没有库存的空仓可以据实完成盘点，不生成虚构行。盘点调整冲销后，原盘点取消并保留事实，重新盘点使用新单据。

字段补项：收发明细增加 `quantity_source`，出库明细增加实称记录关联 `measurement_record`；普通录入记为人工实录，其他来源由专用业务或导入维护。检验单增加 `incoming` 来料类型、批次及收货行关联；工卡变为条件必填，生产检验仍要求工卡。盘点快照日期在草稿阶段允许为空，开始盘点时才写入真实冻结时间。上述均为独立新增迁移。

框架审计参数改为 `audit_request`，避免与业务模型的 `request` 外键冲突；消息接口、示例与扩展说明同步更新，不增加兼容猜测分支。

验证：基础信息、B/C 业务和框架共 196 项 SQLite 回归通过；独立临时 PostgreSQL 5439 上应用完整迁移，并实际通过重复过账与并发出库两项行锁测试。临时 PostgreSQL 已关闭。前端类型检查通过。实际项目迁移前备份：`data-backups/db_before_business_c_20261012_002643.sqlite3`。

## D：工卡、组缸、人工排程与配方采用

接入 12 个生产计划资源。工卡订单分配按明确单位换算，取消工卡释放需求但保留旧分配；下达时分配合计必须等于计划量，无订单建卡必须填写真实依据。下达冻结来源订单行及所有技术要求快照，后续订单变更不会改写原采用。

展开当前有效路线时选择实际节点，保留全部必经节点；未选择的可选节点通过其前置关系绕过。采用计划节点、工艺参数和订单要求在下达后冻结。第一版采用资料包的顺序路线，不增加未经证实的并行依赖。

组缸记录每张工卡的本缸数量及对应订单分配，累计不得超过工卡和订单分配。当前新业务采用相同物料、色标准、路线版本的工卡合缸；历史不符合此规则的组合由导入归档保留，不按新规则改写旧事实。采用配方或排程后冻结缸批成员。

人工排程核对工厂、机台工序适用、工作中心和半开时间区间。相邻时段可以衔接；同缸同工序只生成一笔物理安排。发布、改排和取消是专用动作；改排保留旧版、原因及原安排外键。机台容量只比较已明确 kg 的计划重量与承载量，最低水位等未明确单位不参与计算。

配方采用保留阶段、染化料、原剂量、调整百分比、采用剂量、干料 kg、浴液量/单位、可用浴液密度和计算快照。干料百分数按干料 kg 计算，g/L 必须有明确浴液体积；质量浴比转体积还需实际密度。单位主档明确配置 kg、L 基准及库存单位换算。派生字段按六位精度保存，库存计划量按单位显示位数（最多六位）四舍五入；未舍入剂量、实质计算量及换算倍数保存在快照。计划不生成实称或领料事实。替换采用保留原阶段和明细；旧采用已经生成料单时通过加料/后处理业务处理。

新增字段均无对应旧物理字段，属于明确业务关联或采用快照：工卡 `manual_creation_reason`，订单分配 `adopted_order_snapshot`，排程 `previous_assignment/change_reason`，计划阶段 `bath_density_kg_per_litre`，计划行 `calculation_snapshot`。独立迁移 0007/0008；仍使用原有 `legacy_id`。

生产业务办理/查询角色首次创建时授权；原有角色授权保留，由权限页面配置新增生产动作。页面有路线节点选择、关联明细、人工排程和配方阶段逐项表单，不要求输入内部编号或 JSON。

已在独立 PostgreSQL 验证两项生产并发：同一订单余量只能分配一次，同一机台时段只能安排一次；采购仓储的两项并发仍通过。生产计划和打样共 14 项 PostgreSQL 功能回归通过；完整订单来源快照补项后再通过九项生产测试及正式迁移。基础信息、各批业务及框架共 209 项 SQLite 回归通过，四项跳过的并发已在 PostgreSQL 实际验收。前端类型检查和正式构建通过，项目已迁移和初始化菜单。项目迁移前备份 `data-backups/db_before_business_d_20261012_010356.sqlite3`。

实际项目账号仍启用首次登录改密码流程；登录接口正常，未代用户改密码或关闭该设置。本批未在实际项目录入演示业务，页面整条操作链尚未用现场数据验收。接口业务、页面构建与现场验收分别记录。

同步更正 B 的多轮打样汇总：新轮次可以在上一轮等待回复时继续；迟到的旧回复只更新自身事实，当前状态按最新已经开始的试验轮次及其送版回复汇总，不覆盖最新确板。

## E：实际执行、称量、质量与返修

已接入工序实际开完工、中止、新轮次及更正；合缸使用一笔物理执行与对应成员实绩，整缸更正同时保存成员和物理执行事实，原记录保留。实际占机按开完工区间判断，已中止的实际占用同样保留。时间快照保留完整微秒。更正后的有效事实遵循原字段查询权限，不通过 JSON 绕过字段授权。

料单、实称和净领用分别保存；实称取消采用须先处理关联领料。检验核对实际来源、范围及单位，放行不能超过实际检验覆盖量；终检和复检采用包装前的最后实际产出。返修建立独立路线、执行及复检，承接原订单需求，完成返修须有真实完工、复检通过及有效放行。投入产出谱系引用实际收发，不另生成库存；取消采用后保留历史。

## F：包装、交付、退回与结案

已接入包装实称/固定粒重净重计算、质量处置覆盖量、订单分配及实际 GX98 包装节点。包装累计核对有效放行量和实际产出，采用参数冻结。标签记录请求快照、失败、人工实际成功确认及重打来源。

工卡暂停、恢复、生产完成、结案、重开及未形成包装的需求释放分别办理；重开时联动恢复所属已完成缸批。成品收货、实际交付及客户退回使用实际库存来源，交付保留采用价格。退回先实际入库，重新打开需求须明确；关闭退回单要先重开才能冲销实际收货。订单、采购订单及采购申请支持明确结案和重开，结案不改写原数量。采购申请使用独立状态枚举，避免改变其他审核业务。

新增字段、精度、NULL、关系和计算依据见《本批模型及字段实施清单》《实际执行称量质量字段补充说明》。没有通用异常兜底、猜测外键或用计划代替实际记录的逻辑。

## G：跨模块查询、导出与现场入口
