# Excel 模板导入导出重构方案

更新日期：2026-10-08。状态：X1—X4 代码及接口闭环已实现；X5 导入面板、桌面/窄屏验证及接入说明已完成。Excel/WPS 实际打开和 Android/iOS 真机仍待验收。实际实现、34 项测试、运行包与移动端尺寸证据见 [Excel 实施记录与接入说明](H:/Project_python/django-vue3-admin/djangovue3/docs/Excel实施记录与接入说明.md)。下文保留研究依据与设计规则。

## 1. 已确定的要求

Python 3.14.8、Django 5.2.18、SQLite 保持固定。Excel 工作簿的生成、读取、模板和类型处理统一使用 **openpyxl**，文件只支持 **`.xlsx`**。新增模板、批量更新模板、导入、同步/异步导出和下载中心继续保留。

不复用原项目的 `ImportSerializerMixin/ExportSerializerMixin/import_to_data` 处理代码，也不把当前仅输出字段 key 的简单工作簿包装成“完整模板”。重新编写小型字段映射与工作簿读写函数，保存原项目可用功能，修正已确认的处理问题。遵守直接实现的要求，不设置任意文件大小、行数、列数或导入频次限制，不加兼容引擎、猜测式解析或失败后换引擎。

需要先澄清：**原项目本身也使用 openpyxl，当前简化版同样使用 openpyxl**。本次更换的是模板组织、字段映射和导入/导出方法，不是首次引入这个库。原前端声明接受 `.xls`，但原后台实际调用 `openpyxl.load_workbook`；不能将前端接受声明当成后台已经实现旧二进制 Excel 格式。

## 2. 源码研究结果

| 对照内容 | 原项目实际实现 | 当前项目 | 本次重构 |
| --- | --- | --- | --- |
| 新增模板 | 中文表头、序号、隐藏 `data` 选项表、下拉校验、列宽和表格样式 | 空模板主要是字段 key | 用新的字段定义生成同等可填写模板 |
| 更新模板 | `update_template` 导出现有数据，带“更新主键(勿改)” | 缺少该入口 | 按筛选结果导出带主键的可修改数据 |
| 模板读取 | 根据主键列判断新增/更新，随后依靠固定列位置读取 | 首行字段 key，之后直接读取 | 按明确中文表头映射字段，支持调整列顺序 |
| 选择/关系 | 手工 choices 字典、关系名称转 ID，多对多用广泛分隔正则 | 关系/JSON 主要按 JSON 原值 | 统一正向/反向转换，关系显示可读且能明确定位 |
| 导入保存 | 查实例，传专用导入 serializer；没有实例时可能按新增保存 | `many=True` 仅新增 | 新增和更新分别执行对应业务 serializer |
| 同步/异步导出 | 两处分别写工作簿，异步失败有吞错转同步的路径 | 已有真实异步任务，但只是简单工作簿 | 同一生成函数，明确同步/异步入口及正常任务状态 |
| 文件进入后台 | 先上传附件，再传服务器文件 URL 做导入 | 直接 multipart 上传 | 保留直接上传，由 openpyxl 读取上传文件流 |

需特别修正原方法的这些细节：

1. 固定列位置与 `display` 字段约定容易导致更新模板显示列和读入字段不一致；新方法按表头映射，不靠“第几列应该是什么”。
2. 关系按名称建字典，重名可能覆盖；新模板必须能够区分具体关联对象。
3. 原用户导入配置将“未知/女”的数值映射写反，与模型 choices 不一致；新转换从当前模型 choices 获取，不抄这份错误映射。
4. 原用户导入 serializer 每次保存都重新设置密码，批量修改普通信息也可能重置密码；新更新使用正常用户更新逻辑，不提交密码就保持密码。
5. 原更新主键未匹配到实例时可能转成新增；新更新流程按该主键定位现有可更新对象，不混成 upsert。
6. 空白、`0`、`False`、日期对象应按字段类型处理，不能统一按字符串或真假值决定是否存在。

## 3. 工作簿与字段定义

### 工作簿结构

| 工作表 | 新增模板 | 更新模板 | 普通数据导出 |
| --- | --- | --- | --- |
| 数据 | 第一行中文表头，其后填写；含序号，无更新主键列 | 第一行中文表头；序号、更新主键、现有可修改数据 | 中文表头、序号、可查询/导出的数据 |
| 填写说明 | 字段类型、必填说明、选择项和多值填写示例 | 再说明主键用于定位、空白更新语义、时区 | 按需要说明日期时区、关系等显示含义 |
| 选项（隐藏） | 枚举与关系选项，供下拉和说明引用 | 同上 | 无下拉需求时不生成 |

主表第一行使用唯一的中文标题，服务端字段定义负责标题→字段映射。序号仅帮助阅读，不作为数据库主键。更新列沿用用户可理解的“更新主键(勿改)”标题；数据库主键名称由 Django 模型取得，不能全写死为 `id`。

新增模板保留需要用户填写的业务主键，例如区域 `code`；更新模板的主键只负责定位，不把它同时作为可修改列。

表格样式由 `Table/TableStyleInfo` 生成，实际范围按生成的数据行确定；空模板可以保留一行空白填写区，该行不会创建数据。冻结首行、合理列宽、日期/数字/文本格式、字段说明用 openpyxl 原生能力完成。列宽是显示样式，不限制实际内容长度。不合并数据区域单元格，不把说明行混入业务数据。

隐藏选项表配合命名区域及 `DataValidation` 提供单选下拉。可填写列的下拉范围覆盖后续填写区域，不采用随意固定的 100/1000 行上限。openpyxl 负责写入下拉规则，实际业务值仍交给既有 serializer 校验；该库不会替服务端执行 Excel 下拉规则。[官方下拉说明](https://openpyxl.readthedocs.io/en/stable/validation.html)、[表格说明](https://openpyxl.readthedocs.io/en/stable/worksheet_tables.html)。

### 字段定义方式

用一份普通 Python 字段定义表达：字段 key、中文标题、适用新增/更新/导出、类型、选项或关系显示方式、显示格式。字段基础信息来自 Django 模型和现有 serializer；只有专用标题、计算展示列、业务关系显示等需要模块显式配置。

新增、更新和普通导出的列可以不同。用户普通导出可以含最后登录、部门负责人等展示列，更新模板只含可修改列。写入时的必填、默认值、唯一性、关系和权限仍由现有业务层处理，不再复制一套模型校验器。

首个用户模板按原实际字段范围配置 `username/name/email/mobile/gender/is_active/dept/role`，对应登录账号、用户名称、用户邮箱、手机号码、用户性别、账号状态、部门、角色。更新模板在这些业务列前添加序号和更新主键；普通导出另配置部门负责人、最后登录等展示列。用户模型里的权限标志、审计字段及密码散列不会因为自动枚举模型就混进用户模板。其他模块同样先明确自己的业务列，再复用同一读写方法。

普通 JSON 字段使用 JSON 文本；关联字段使用其专用可读映射，而不是让用户手填 `[12, 34]`。模板不会承担二进制附件上传；需要导入的文件地址字符串按其业务字段处理，附件上传仍使用现有上传流程。只读日志/任务结果等页面保留数据导出，不提供没有业务含义的模板导入。

## 4. 导出与导入的类型转换

| 类型 | 写入 xlsx | 读回业务值 |
| --- | --- | --- |
| 字符串/编号/手机/主键 | 文本单元格；保留前导零及长编号；文本以 `=` 开头也按文本保存 | 保留字符串内容，主键按实际模型类型转换 |
| 整数/金额 | 数值单元格、字段对应显示格式 | 交给 Integer/Decimal 等 serializer 字段；`0` 是有效值 |
| 布尔/枚举 | 模型或业务 choices 的中文标签及下拉 | 标签映射为真实值；`False` 不是空白；性别等不手写错配字典 |
| 日期/时间/日期时间 | 原生 Excel 日期/时间值和相应 number format | 接受 openpyxl 日期对象；文本填写按说明中的明确格式转换 |
| 外键 | 可读显示名称加主键，例如 `财务部 [18]`；部门可显示路径 | 对应选项转换为实际主键，不按重名名称取第一条 |
| 多对多 | 以分号分隔可读选项；含分号/引号的名称使用标准 CSV 引用规则 | Python 标准库 csv 解析多值，再映射为主键列表；读写使用相同规则 |
| JSON/数组 | 明确 JSON 文本 | JSON 解析后传给相应字段，不吞掉解析错误 |

关系选项复用当前页面该字段的业务可选集合；同名对象通过主键区分。更新模板还要正确呈现已关联对象，不能因选项展示问题把既有关系改空。具体关系显示规则在字段定义中表达，不再硬编码 `values_name='name'`。

多对多示例：`财务 [12];采购 [34]`。如果单个选项名本身含分号，该项按 CSV 规则加双引号。导出、说明和导入共用该编码规则，避免原正则把名称里的空格或标点当成分隔符。**普通 xlsx 下拉是单值选择，不能宣传成可直接点击多选**；多对多按上述文本填写，模板给出选项和示例，保持无宏工作簿。

日期时间统一按项目 `TIME_ZONE` 展示，写入前转到该时区再移除 tzinfo，读入后交给 Django 的当前时区规则。xlsx 不携带时区信息，不能仅去掉 UTC 的 tzinfo 就当成本地时间。[官方日期/时区说明](https://openpyxl.readthedocs.io/en/stable/datetime.html)。

openpyxl 不计算公式。读取采用 `data_only=True`；用户用公式准备数据时，导入使用 Excel/WPS 已计算并保存的缓存结果，没有缓存结果时读到的是空值，按下节空白语义处理，不代表公式已计算。模板说明写明先计算并保存；生成的模板本身使用实际值。[官方公式能力说明](https://openpyxl.readthedocs.io/en/stable/simple_formulae.html)。

## 5. 新增与批量更新流程

### 新增

下载新增模板 → 填写中文列 → 上传 xlsx → 按表头映射 → 类型/关系转换 → 调用对应新增 serializer → 提交并刷新列表。

空单元格不提交字段，使用正常新增默认值；必填项缺失由对应 serializer 报错。序号和整行空白不生成数据。`0`、`False` 不属于空白。用户新增的默认密码继续读取现有配置，不改成旧 MD5 方法。

### 更新

在当前筛选条件下下载更新模板 → 保留更新主键 → 修改需要更新的内容 → 上传 → 定位现有可更新对象 → 调用 `partial=True` 的正常更新 serializer → 提交并刷新。

读取以“更新主键(勿改)”列区分更新模式；新增模板无该列。一个工作簿执行一种模式，不为没有主键的更新行猜测新增。主键不存在或不在已有更新范围时，返回带行号的业务错误，不创建替代记录。

沿用原空白语义：**更新时空单元格不提交，原值保持；删除整列也不修改该字段**。本轮不加入特殊“清空标记”。如果要清空已有字段，可通过平台现有编辑操作完成；这项选择写入模板说明，避免把擦掉单元格误认为清空数据库值。

同一主键出现多行时按工作表顺序执行，后面的有效字段值覆盖前面的值，不额外禁止重复行。更新用户普通信息不重置密码；用户部门更新走修正后的同一保存逻辑，同步 `dept_belong`。多对多通过正常 serializer 保存，不绕开业务处理。

主键从提交内容中提取用于定位，不因为 serializer 将 ID 设为只读而丢掉定位信息。列移动按标题识别；模板允许删掉不需修改的业务列，更新主键列仍负责定位。明确的表头拼写/字段类型错误返回具体位置，不猜别名、不跳过错误伪报成功。

一个文件的保存使用一个普通 `transaction.atomic()`：出现业务错误整文件回滚，用户修正后再次导入。逐行读取和保存，遇到错误返回工作表、实际行号、字段、说明，例如“数据，第 8 行，所属部门：该选项不存在”。不预先读取全表再复制成多个大列表，也不额外生成错误工作簿/审批流程。

## 6. 查询、权限及导出方式

下载更新模板和普通导出使用当前筛选条件，包括 URL 中的部门/父项上下文；取全部匹配结果，不只当前分页。更新模板的数据和列还需具备对应查询与更新权限；提交时重新使用现有更新数据范围，不依赖下载时的旧状态或隐藏工作表作为授权依据。

新增模板按 `is_create` 生成列；更新模板按可查询且 `is_update` 的字段生成列；普通导出按 `is_query` 生成列。密码只可能作为明确新增/重置的写入输入，已有密码散列不进入导出。审计字段的创建人、修改人、归属部门等仍由后台正常填写。

这些是现有接口和字段权限的复用，不增加 Excel 专属权限层级。新增更新模板入口按现有菜单按钮登记方式接入。

保留同步、异步两个明确入口，不按任意记录数自动换方式。两者共用同一字段定义、值转换、样式和工作簿生成函数。异步继续使用已有 Celery、Redis 与下载中心，保存文件名、大小、MD5 和任务状态，失败按正常任务机制记录并暴露，不吞异常转同步或返回假成功。

本轮先沿用当前任务传输链路：将已经按权限筛选的行数据和可序列化字段描述交给 worker，再用相同生成函数写文件；不会借 Excel 重构另造调度框架。将来如实际负载需要把查询也移入 worker，另行按证据改进。

模板生成使用普通 Workbook，以直接保留表格样式、说明和下拉；导入使用 `read_only=True` 逐行读取并关闭工作簿。普通大数据导出若经实际测量确需优化，可用 `write_only=True`，但要核对 Table 表头及数据校验等能力，不用两套结果不同的模板实现。输出优先写临时文件并返回 FileResponse/保存下载文件，避免不必要的全文件字节复制。[官方读写优化模式](https://openpyxl.readthedocs.io/en/stable/optimized.html)。

## 7. 页面与移动端

导入面板提供“下载新增模板”“下载批量更新模板”“选择/拖入 xlsx”“提交”和结果说明。文件选择框 `accept`、显示文案、下载文件名和服务端读入格式统一为 `.xlsx`；服务端也执行这一格式约定，不能只改前端 accept 就继续接受其他工作簿类型。前端不解析或重新生成工作簿，导出文件全部来自 openpyxl 后台。

FastCrud 的间接 SheetJS 依赖不作为本业务的模板引擎，也不新增浏览器端 Excel 处理链路。是否可移除依赖由后续实际依赖关系决定，不为这一要求强行破坏 FastCrud。

手机面板满宽或按可用宽度缩放，按钮换行、错误信息可读，底部提交/取消可见；手机通过系统文件选择器上传，拖放仅为电脑操作方式。手机导出沿用文件下载，Android Chrome/iOS Safari/WPS 打开与填写后上传需实际验收，不以桌面缩窄视口替代真机结果。
