## 逐项证据与补齐方向

### F01 · P1 · 接口排除字段被展示配置重新加入

**差异与影响：** 同一字段既在 serializer_exclude_fields 中，又在 fields 中设置标题/展示配置时，CoreSerializer 先删除字段，再把它补成 ReadOnlyField。独立岗位配置排除 code 后仅为 code 设置标题，详情仍返回 code=AUDIT-ONLY，状态 200。接口排除没有生效；这不是只排除 UI 的 exclude_fields 行为。

**证据：** 内存接口实测。[字段构造顺序](H:/Project_python/django-vue3-admin/djangovue3/backend/core/api.py:17)；[扩展契约](H:/Project_python/django-vue3-admin/djangovue3/docs/框架扩展与组件接入.md:82)。

**最小补齐方向：** 按现有三个配置项的定义处理优先级：API 排除决定序列化字段是否存在，展示定制只作用于允许输出的字段。验证排除与标题/source/列配置组合，不加入新的排除规则。

### F02 · P1 · xlsx 导出未接通虚拟字段与用户字段排除

**差异与影响：** 配置 Post.summary 的 source=name 时，详情可正常返回摘要，但同步导出在 model_fields[summary] 抛 KeyError。Users 排除 mobile 后，固定 USER_EXPORT 仍索引该序列化字段，也抛 KeyError。异步导出在提交任务前复用同一列构造，所以同样受影响。默认实体导出已完成，不应因此写成“Excel 整体未实现”。

**证据：** 内存接口实测 + 共用调用链。[导出列](H:/Project_python/django-vue3-admin/djangovue3/backend/system/excel_fields.py:42)；[同步与异步共用列](H:/Project_python/django-vue3-admin/djangovue3/backend/system/excel.py:144)；[原用户专用导出](H:/Project_python/django-vue3-admin/django-vue3-admin-master/backend/dvadmin/system/views/user.py:167)。

**最小补齐方向：** 沿用 openpyxl/xlsx，按有效序列化字段构造导出列，明确只读虚拟 source 的导出取值；用户固定列与实际字段集合相交。分别验普通字段、虚拟字段、被排除字段以及同步/异步输出。

### F03 · P1 · 部门用户和角色成员仍有额外接口权限依赖

**差异与影响：** 普通角色有 user:list，可以直接查询部门及下级用户（200），但部门 info 为 403。含下级开关先调用 departmentSummary，统计成功后才刷新用户，因此合法筛选被统计接口阻断。角色有 role:users-get，成员接口为 200，RoleUsers 挂载却先等 dept/tree（403）才加载成员；全局 403 处理还会跳转 /401。原 all_dept 是登录可用的字典接口，dept_info 单独放行。上轮去掉父标题详情请求没有覆盖这两个分支。

**证据：** 内存接口实测 + 前端调用顺序。[部门统计调用](H:/Project_python/django-vue3-admin/djangovue3/web/src/components/ResourceTable.vue:139)；[成员挂载依赖](H:/Project_python/django-vue3-admin/djangovue3/web/src/components/RoleUsers.vue:2)；[原部门选项](H:/Project_python/django-vue3-admin/django-vue3-admin-master/backend/dvadmin/system/views/dept.py:129)；[原部门统计](H:/Project_python/django-vue3-admin/django-vue3-admin-master/backend/dvadmin/system/views/dept.py:165)；[403 跳转](H:/Project_python/django-vue3-admin/djangovue3/web/src/api.ts:25)。

**最小补齐方向：** 拆开筛选与统计依赖，并为成员部门筛选使用与该业务授权相符的选项来源；保持原有数据范围。用仅有子页面/成员读取权限的普通角色验收，不给角色附加整套部门管理权限来掩盖问题。

### F04 · P1 · 关联选择调用特殊资源时缺少视图动作上下文

## 明确不同的实现契约与取舍

这些仍需开发者知道，但与上述 18 组确认缺口分开记录。

| 内容 | 当前方案与差异 |
| --- | --- |
| 运行版本/库适配 | 固定 Python/Django，用替代库/外嵌补丁接新环境；审计不自动升级锁文件，本轮未在线重新声称全部依赖为 latest |
| 数据库/代理 | SQLite 保存业务/权限/任务数据，Redis 作代理及共享通知；MySQL 不计缺失 |
| Excel | 新 openpyxl/xlsx、中文表头与当前导入协议；空白保持值、0/False 有效、整文件回滚、更新不存在不新增；旧引擎/URL 导入和错误性别映射不恢复 |
| 字典/xlsx 选项 | 页面采用运行时字典，xlsx 采用模型 choices；改字典中文标签不会同步改变模板。属于既有明示方案，若要一致需另改字段映射 |
| 登录/密码/重置 | 当前 Django 哈希，不叠加旧 MD5，不恢复五次锁定。重置会清 pwd_change_count 并触发首次改密，原重置未清计数；这是确有差别的当前行为，后续保持或调整须写清，不为核对而改正式密码 |
| 权限/数据范围 | literal/<built-in function id>、启用角色、多角色授权并集，修正旧混入无关按钮、本人范围提前返回等问题；旧客户端/数据库不直接兼容 |
| 共用模型/插件 | modifier 外键、显式 request、Area.code 主键；旧 DATA/DICT_DATA/便捷方法、逐动作 serializer 辅助属性及 mixin 不保证原样可用，以当前 ORM/DRF/扩展契约接入 |
| 消息 | 接收记录驱动收件、Redis 共享通知、重复发布补新接收者；不复制旧重复接收/漏收件错误。JSON 初始化数据不能当成消息发布入口 |
| 风格与组件协议 | 共享 Resource/FastCrud、Element Plus/Iconify、新插槽/事件命名、文件选择器链接样式和固定 10 条分页，与原非像素一致；旧选择器可调页大小未完全同样提供，属于附带交互差异，不等于选择/分页功能不存在 |
| 日历/锁屏/首页 | 日历完整周展开、真实密码解锁、平台卡片首页与本地条款；不恢复原六周截断、仅前端解锁或原组织条款文本 |
| 文档/退出/桌面 | OpenAPI 3/Bearer、退出清理本地状态；原 LogoutView 没有 JWT 吊销能力。便携目录包无 InstallForge 安装器，未复制原无效监测/通用进程强杀 |
