## 扩展契约与数据迁移

Menu.resource 表达真实接口资源，component_name 表达页面组件名称/按钮权限前缀。例如 resource=post、component_name=custom_post，列表读 post，按钮值为 custom_post:list。迁移 0016 从既有通用菜单的 list 按钮 API 识别资源；没有对应按钮时取原 component_name。原自定义菜单若没有可识别的按钮，需在已有菜单编辑界面填写实际资源。生成按钮会保存所选资源及实际修改人。新按钮和图表示例菜单不会自动扩大既有角色授权。

AppConfig.resource_options 仍以模型类名为键。crud_fields 设置 UI 顺序；exclude_fields 只排除 UI，API 是否输出由 serializer_exclude_fields 单独控制。fields 可为只读虚拟字段指定 source，来源为模型属性/方法，不执行配置中的代码；后台读取权限仍跟随源字段。column/form 和 crud_options 在前端深合并。需要函数的扩展写在正常 TypeScript 组件/插件中，不能把 JSON 当作可执行脚本。旧 FastCrudMixin 和逐动作 serializer 辅助属性不保证原样兼容，使用当前 DRF 覆写方式接入。完整例子见 [框架扩展与组件接入](H:/Project_python/django-vue3-admin/djangovue3/docs/框架扩展与组件接入.md)。

配置反查为 GET /api/system/system_config/relation_info/，参数 var_name、table、relation_ids（主键逗号分隔）。仅查询当前操作者正常范围内的配置，不另设旧 get_relation_info 拼写兼容入口。

角色默认预设只初始化新勾选；已有授权不因切换预设或批量选中而改变。可分配部门标记属于编辑交互，没有附加原项目之外的安全策略或任意限制。
