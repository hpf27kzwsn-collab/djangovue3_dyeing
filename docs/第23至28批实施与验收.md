## 本批选择

1. 用户必填规则恢复在原使用位置的新增/编辑表单；不把所有可空模型变成后端统一非空。创建 UI 默认性别 1，模型/API 默认 0 保持已有契约。
2. 可配置关联使用 lowercase `setting.primarykey`，不强迫换成数据库 id，修订 D100 的限制性方案。
3. 文件/日历预期规则错误使用 Element Plus 的校验回调，不捕获或吞掉 API、解析和上传故障。
4. 部门选项属于用户/成员流程依赖；人数查询仍按用户数据范围，不开放部门管理 CRUD。
5. 版本身份由一次 Vite 构建同时写入客户端及后端文件；检测在导航触发，不额外创建轮询和重试服务。
