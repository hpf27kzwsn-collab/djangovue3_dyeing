# 实际执行、称量、质量字段补充

本补充使用当前 Django + Vue3 项目。新增字段用于保存资料包要求的实际事实、数量范围和更正历史；没有直接旧物理字段的，不声称是旧字段复刻。既有旧字段、精度、NULL 和 `legacy_id` 保留。

| 对象 | 新增字段或模型 | 含义及依据 |
| --- | --- | --- |
| PhysicalBatchExecution | 缸批、实际工序、机台、轮次、人员、班次、实际开始/结束、本缸实际 kg、状态 | 同缸只保存一次物理执行；工卡执行关联这次执行，分别保存成员实际量。资料包拆合缸及 M08 |
| PhysicalExecutionCorrection | 原物理执行、更正时间、员工、原因、前后整缸事实、逐成员对照 | 整缸更正一次提交全部成员，成员 kg 合计等于整缸 kg；原值不覆盖 |
| OperationExecution | physical_execution | 同缸成员分配来源。各成员实际量不能复制全缸实际量 |
| ExecutionCorrection | before_values、after_values | 每次更正前后有效事实；未选择的字段保持原值，选择清空与未修改分别处理 |
| WorkCardOperation | is_skipped、skip_reason | 仅已选、非必经且工序允许跳过的节点可明确跳过；已有实际执行不能改为跳过 |
| WeighingRecord | void_reason、voided_at | 作废保留原实称；已被有效领料采用的实称先处理领料 |
| QualityInspection | inspected_quantity、quantity_unit | 明确本次所检实际执行、包装或来料的覆盖数量；不以工卡计划整体放行 |
| QualityInspection | is_void、voided_at、void_reason | 取消采用保留原判定与检验项目；有效库存处置和返修引用先处理 |
| QualityDisposition | status、supersedes | 按实际覆盖量形成放行、让步、隔离、返修等处置；替换保留原记录 |
| LotTransformation | is_confirmed、confirmed_at | 谱系对应已生效实物收发；确认谱系不会另生成库存流水 |

全部新增模型继承 ErpModel，包含额外字段“旧系统id”。旧事实找不到明确来源时保持 NULL，不根据新编号猜旧编号。

计划料单、有效实称、净领用分别汇总。净领用等于有效出库减实际退料，实称只汇总未作废记录。采用具体实称的出库按同一笔实称汇总整单各行，累计净采用不得超过有效实称；人工实际录入不由计划量代替。

实际工序可以跨日、多轮执行。最新有效前置轮次完成后才能开后续工序，实际时间必须顺序一致。更正不得越过工卡下达、前置完工或后置开工；已有有效检验或实物下游采用时，先处理对应下游。返修建立关联原工卡的新工卡及路线；原实际执行不改写。返修开工、复检和合格放行结案分别记录。

实现使用明确模型字段和业务规则，不增加旧名猜测、吞异常、计划量兜底或虚构实测记录。设备协议尚未提供，人工实测来源可以正常办理；实际采集回执需按在用设备接入。
