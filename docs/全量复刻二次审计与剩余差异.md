### R01 · P1 · 字典子项新增默认值不完整

**原行为：** 子项表单隐藏 is_value，并固定为 true；提交时带当前父字典。

**当前状态：** 通过行按钮进入 ?parent=ID 后，parent 会填入，但 is_value 仍取模型默认 false。只有点击左树 filterTree 才设置 true。当前字典数据接口又明确过滤 is_value=True。

**触发与影响：** 字典行的“字典配置”→新增→未手动打开“字典项”开关→保存：管理列表有记录，业务下拉取不到。

**最小修正方向：** 在字典子项上下文统一设置 is_value=true；根项和子项分别表达默认值，不依赖用户先点击树。

**证据：** [原实现](H:/Project_python/django-vue3-admin/django-vue3-admin-master/web/src/views/system/dictionary/subDict/crud.tsx:306)；[当前实现](H:/Project_python/django-vue3-admin/djangovue3/web/src/components/ResourceTable.vue:48)；[当前实现](H:/Project_python/django-vue3-admin/djangovue3/backend/system/views.py:464)。

**核验级别：** 已用内存数据库复现默认 false 和下拉返回空；行按钮到新增默认值由源码调用链确认。

### R02 · P2 · 字典主列表混入子项，根/子操作语义未区分

**原行为：** DictionaryViewSet.list 在没有 parent 时只返回根字典；子项使用独立子表。

**当前状态：** 通用列表无默认根过滤；根、子项混列，每行都显示“字典配置”。字段可编辑范围也未区分根项与子项。

**触发与影响：** 直接打开字典页面，会同时看到根和具体值；对子值仍能继续进入“字典配置”。

**最小修正方向：** 保留通用组件，按根/子上下文限定列表和操作；不用恢复两套重复 CRUD。

**证据：** [原实现](H:/Project_python/django-vue3-admin/django-vue3-admin-master/backend/dvadmin/system/views/dictionary.py:72)；[当前实现](H:/Project_python/django-vue3-admin/djangovue3/backend/core/api.py:67)；[当前实现](H:/Project_python/django-vue3-admin/djangovue3/web/src/components/ResourceTable.vue:67)。

**核验级别：** 源码确认；界面组合未在本轮浏览器重演。

### R03 · P1 · 部门、字典的删除关系与原项目不同

**原行为：** Users.dept 为 PROTECT；Dictionary.parent 为 PROTECT。有用户引用的部门、存在子项的父字典不能按普通删除直接删掉。

**当前状态：** Users.dept 改为 SET_NULL；Dictionary.parent 改为 CASCADE。当前普通删除会清空用户所属部门，或连带删除全部子字典。这两项业务取舍未在既有记录中明确解释。

**触发与影响：** 删除一个有成员的部门；删除一个已有具体值的父字典。

**最小修正方向：** 按原业务引用关系对齐删除语义；这是已有模型规则，不是新增保险式限制。不要用一套额外删除校验框架替代模型关系。

**证据：** [原实现](H:/Project_python/django-vue3-admin/django-vue3-admin-master/backend/dvadmin/system/models.py:40)；[原实现](H:/Project_python/django-vue3-admin/django-vue3-admin-master/backend/dvadmin/system/models.py:351)；[当前实现](H:/Project_python/django-vue3-admin/djangovue3/backend/system/models/organization.py:57)；[当前实现](H:/Project_python/django-vue3-admin/djangovue3/backend/system/models/resources.py:10)。

**核验级别：** 内存数据库实测：删除部门后用户 dept=null；删除父字典共删除 2 对象，子项消失。

### R04 · P1 · 普通用户更新接口仍接受密码，与专用密码流程不一致

**原行为：** UserUpdateSerializer 将 password 设为只读；个人改密、重置密码走各自流程。

**当前状态：** 前端 PATCH payload 排除 password，但 UserSerializer.update 仍接受并 set_password；该入口不执行重置接口的超级管理员条件、确认输入和 pwd_change_count=0 语义。Excel 特定字段白名单没有走此问题路径。

**触发与影响：** 直接向具有普通用户修改权限的接口提交 password；不需要点击前端的重置按钮。

**最小修正方向：** 普通更新与原项目一样不修改密码；新增及现有专用密码接口分别保留自己的语义。

**证据：** [原实现](H:/Project_python/django-vue3-admin/django-vue3-admin-master/backend/dvadmin/system/views/user.py:135)；[当前实现](H:/Project_python/django-vue3-admin/djangovue3/backend/system/serializers.py:142)；[当前实现](H:/Project_python/django-vue3-admin/djangovue3/backend/system/views.py:62)。

**核验级别：** 内存数据库 serializer 实测：密码改变，原 pwd_change_count=5 保持；入口权限分支已核对源码。

### R05 · P2 · 普通用户管理范围包含超级管理员，表单暴露额外账户字段

**原行为：** UserViewSet 默认排除 is_superuser；原用户表单不提供 is_staff/is_superuser 操作。

**当前状态：** 当前 UserViewSet 查询包含超级管理员；通用元数据/表单可展示并提交继承的 is_staff/is_superuser，以及 first_name/last_name 等字段。角色授权用户面板却仍排除超级管理员。

**触发与影响：** 在普通用户列表查看超级管理员、编辑其管理字段，或给普通用户修改这些继承字段。

**最小修正方向：** 统一普通用户管理的对象范围及可编辑字段，与原专用用户流程对齐；若保留差异，应单独记为业务取舍，不能称为完全复刻。

**证据：** [原实现](H:/Project_python/django-vue3-admin/django-vue3-admin-master/backend/dvadmin/system/views/user.py:231)；[当前实现](H:/Project_python/django-vue3-admin/djangovue3/backend/system/views.py:46)；[当前实现](H:/Project_python/django-vue3-admin/djangovue3/backend/system/serializers.py:114)。

**核验级别：** 内存数据库确认查询集含超级管理员；字段暴露由元数据与通用表单确认。

### R06 · P2 · 个人中心缺性别编辑、部门/角色可读信息和最近消息

**原行为：** 个人中心显示部门名称、角色标签及最近消息，基本资料可编辑性别。user_info 也返回 user_type、dept_info、role_info。

**当前状态：** Profile 只有头像、姓名、邮箱、手机号和密码；AccountSerializer 有 gender 但 UI 无输入，有关系 ID 但没有组织名称信息，也未返回 user_type。最新消息接口存在，个人中心没有使用。

**触发与影响：** 打开个人中心，无法完成原有的性别编辑，也看不到本人组织信息和消息摘要。

**最小修正方向：** 补回原页面已有信息及编辑项，复用现有消息和用户序列化能力。另：当前个人接口不含 last_login；原个人接口也不含，属于上轮 B02 验收表述错误，不算原项目缺失。

**证据：** [原实现](H:/Project_python/django-vue3-admin/django-vue3-admin-master/web/src/views/system/personal/index.vue:46)；[原实现](H:/Project_python/django-vue3-admin/django-vue3-admin-master/backend/dvadmin/system/views/user.py:274)；[当前实现](H:/Project_python/django-vue3-admin/djangovue3/web/src/pages/Profile.vue:12)；[当前实现](H:/Project_python/django-vue3-admin/djangovue3/backend/system/serializers.py:32)。

**核验级别：** 缺少 UI 由源码确认；内存探针确认个人接口不含 last_login。

### R07 · P2 · 个人资料手机号唯一规则未保留

## 对此前文档结论的修正

1. “第 9—13 批已实施”只表示当时清单对应改动已落地，不能解释为所有原功能、逻辑、细节都完全相同。本报告是剩余差异的最新依据。
2. 原 B02 中“账号/个人接口返回实际 last_login”不准确：当前只在普通用户序列化/列表和导出链有最后登录时间；AccountSerializer 没有。原 user_info 本身也不返回 last_login，因此应修正文档，不能伪造一项原功能。
3. 原 F/扩展项目把远程选择、通用字符串主键与自动 CRUD 作为整体已实现，粒度过粗：组件、单条接口已存在，R10/R15/R16/R25 说明实际接入/批量/控件/覆盖入口仍有边界。
4. 字典类型编辑中的动态日期/上传等逻辑在原 .tsx 有大段注释，不能把注释代码算成活跃能力遗漏。原实际头像组件有上传能力，另一个 cropper 演示的注释提交也不能说明所有头像裁剪是假实现。
5. 本轮最初怀疑 import/ 是旧错误地址；进一步检查 @action(url_path="import") 并实际 resolve 后确认它正确。R11 只记录真实的动作缺漏和路径推导问题。
