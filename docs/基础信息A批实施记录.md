## 1. 页面和模型

接口路径为 `/api/system/erp_base_<模型小写名>/`，字段配置路径为 `/api/meta/erp_base_<模型小写名>/`。字段配置、保存服务、序列化和页面均登记到现有扩展框架。

## 2. 保存规则

- 普通新增、修改、批量修改和 xlsx 导入统一调用基础资料保存服务及模型 `full_clean()`；检查实际字段和现有约束。
- 一个主体可兼任客户、供应商和外协方。联系人及地址固定归属主档；地址的联系人必须属于同一主体。
- 设定默认联系人时撤销该主体原默认；默认地址按主体与地址类型分别切换。操作在同一事务内完成，字段或关联校验失败时完整回退。
- 字典上级必须属于同一数据类型。主体、字典及库位上级不能形成循环；已有下级的字典不能改为不同数据类型。
- 库区无上级，实际库位可归属同仓库库区；库位不可换仓库，已有下级库位的库区不能改为实际库位。
- 纱线/织物规格和染化料资料分别检查物料类型。物料已被规格或业务引用时，不能改写类型或库存单位。
- 单位转换沿用 `Unit.convert_quantity()`：相同维度与基准下按倍率换算。单位被引用后不能改写维度、基准或倍率，避免改变既有数量含义。
- 机台工作中心必须属于同一工厂。已有引用的机台及工作中心不能迁移工厂。
- 从属资料创建时采用主档的数据归属部门。关联选择与写入沿用现有查询、操作和部门数据范围权限。

这里的校验是明确的业务规则。保存失败会返回具体字段原因；没有补造默认外键、猜测字典用途、备用字段或静默成功逻辑。

## 3. 路线版本

流程为“草稿 → 审核 → 启用 → 停用”。审核后版本字段及节点冻结，调整通过“复制新版本”建立新草稿。

| 操作 | 条件及结果 |
| --- | --- |
| 审核 | 草稿必须有节点；验证工序号、同版本前置节点及先后关系 |
| 启用 | 仅已审核版本可执行；改为使用中 |
| 停用 | 已审核或使用中版本可执行；保留原版本与节点 |
| 复制新版本 | 同路线使用最大版本号加一；复制节点并重新关联新前置节点，结果为草稿 |

生效/失效时间同时填写时，失效须晚于生效。标准时长不能为负数；修改前置节点工序号时，仍须早于引用它的后续节点。普通保存不能直接修改版本状态，批量修改、导入和删除也执行冻结规则。

复制版本不复制旧系统id、生效/失效时间或原创建人；新版本与节点保留业务备注，重新记录本次操作者。路线版本按独立版本启用，本批不新增“同路线只能有一个使用中版本”的规则，产品适用与后续工卡采用在对应业务批次实现。

本批冻结的是路线版本及节点。标签模板在此批维护文件与版本号，F 批再实现打印采用、模板快照和重打事实。

## 4. 字段复刻及合理调整

所有模型原有 `legacy_id` 保留。基础资料详情中只读展示，普通新增、修改和 xlsx 导入不能写入；新记录及复制版本为 NULL，后续来源导入使用既定的 schema、table、完整 key JSON 文本。

旧可空文本继续区分 NULL 与空串，文本首尾空格不自动裁掉。可空布尔分别表示“未填写、是、否”，数值明确零与未填写分别保存。清空可空小数字段写为 NULL。

机台 `number` 对应旧 `p_Machine.MachineNo`，旧列允许 NULL。现有新模型原来允许空输入却使用非 NULL 的唯一文本列，导致第二台没有编号的机台无法建立。本次改为 `null=True`，空输入保存 NULL，已有空串随迁移转为 NULL；填写编号时仍沿用已有唯一约束。内部机台业务身份继续使用工厂及 `code`，显示编号不用于业务外键。文本存储与旧 smallint 的类型差异仍按原字段差异说明处理。

`ColorStandard.source_sample` 是后续打样来源关系，本批只读；B 批在打样确板业务动作中填写。字典数据类型按旧值维护，当前不把未核实的代码集合编成默认值，也不推算粒、筒、箱之间的换算。

## 5. 角色及初始化

新增两个专用角色：

- **基础资料维护**，权限字符 `erp_base_manager`：26 个模型的维护与路线业务动作；旧系统id、版本状态、来源打样关系按上述规则只读。
- **基础资料查询**，权限字符 `erp_base_viewer`：基础资料查询、详情及同步导出。

两个角色均包含主档及从属入口和所需部门、账号、附件选择权限。维护角色可通过文件选择器上传附件；没有追加账号或部门修改权限。

重复执行 `init_data` 更新本批菜单位置及组件，保留现有密码与授权设置，不重新补回已调整的角色权限。已有超级管理员可以直接使用基础信息；普通账号在现有角色配置中分配上述角色。
