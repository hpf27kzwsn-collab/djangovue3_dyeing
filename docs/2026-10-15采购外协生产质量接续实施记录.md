# 2026-10-15采购、外协与生产质量接续实施记录

本批按最新已保存的原结构、程序和入口配置继续实现Django服务。原表数据、字段及旧erpID保持承接关系；未关闭分支继续列入方案，不因异常、空表或使用少而移除。

## 本批具体交付

| 模块 | 入口/动作 | 本批实现 |
|---|---|---|
| 采购 | 采购单和机物料/染化料申请的修改、删除、反审 | 分别核查原PurchaseOrders和PurDetailNo引用；整单、明细新增/修改/删除在同一服务执行原范围；修正原游标覆盖问题 |
| 采购 | 采购明细“查询原采购收货进度” | 汇总18类坯料、20类半成品实际WeightQty；返回参与原行、原待收选择可见性；保留NULL、负数 |
| 采购、仓储 | “按实际分批量生成收货单” | 原采购明细→采购坯料/半成品入库；独立输入本次量、粒数、时间、仓库、单位；原采购量不改，金额按原精度计算 |
| 销售、生产 | 订单颜色“查询原外协待申请量” | 原订单量＋OutQty－实际有效合单量－已有半成品申请量；原过滤条件独立显示，负余额仍返回 |
| 销售、生产 | “按明确数量生成外协申请” | 支持OutWorkApply及SemiOutWorkApply两类；缺父项、多候选、NULL及负数保留，完整来源留档 |
| 生产、仓储 | 申请明细“按实际量生成外协发出单” | 坯料走GrayOutWork、半成品走SemiOutWork；用实际输入量及实际工卡号，保留申请量和实际发出量区别 |
| 仓储 | 发出明细“按实际量生成外协回货成品单” | 按ProdInWork生成多批回货，原发出量不覆盖，不自动推定损耗或结案；负数及NULL可表达 |
| 质量、生产 | 对色检查保存/删除 | 按曲线实际步骤累计DefaultValue至RealValue；生成班组人员；修改/删除只撤回本检查生成的人員，历史人员保留 |
| 质量、生产 | 疵布入库明细新增/删除 | 正粒数新增写工卡“疵布入库处理”及9状态；删除按原程序范围恢复工序，保留历史工卡身份 |
| 质量 | “查询原疵布收发余额” | 三种数量分别入减出；负数、孤立出库、全NULL及仅长度项不隐藏，另标注旧库存查询可见性 |
| 质量 | 内部评审、客退评审删除 | 按原JobSheet.LossStr实际回修引用限制删除；其他评审不擅自套用 |
| 生产 | 刷卡保存 | 同工卡染色后续状态继承起始机台；原指定工位/工序配置清零六项产量；新EndTime空值采用原保存时刻规则 |

计算、生成、回写和事务分别位于source_purchase_flow.py、source_outwork_flow.py、source_quality_flow.py及现有source_services.py；source_api.py仅处理参数、权限和响应。动作经生成器登记到原模型页面，可在主从明细中调用。新增9个具体模型动作权限已登记。

数量输入采用十进制文本，支持负数及NULL，避免浏览器浮点数先改变大数；保存按原目标字段精度舍入。新生成单据没有旧erpID，来源旧erpID和完整字段快照保存在对应单据上下文，原历史记录仍可查询。

## 已核实的库存时点

PurGrayIn、PurSemiIn、GrayOutWork、SemiOutWork、ProdInWork均为保存即更新库存。生成新单据时即调用现有原库存服务，审核不另外增加一份流水。反审核恢复可编辑状态并按当前单据重建有效流水，不清空库存；修改数量更新本单流水；删除可删除的新单据撤回其生成流水。

这是本批查询原入口配置及回归测试得到的具体结论，不能套用“所有单据审核才生效”的统一假设。外协申请本身不产生库存。
