# 班次循环、班组日历及工序机台选择实施记录

日期：2026-10-15；第十八批；分支：feature/erp-seven-module-models。

本批补齐循环排班、按机台查班组、工序可选机台和进缸机台提取。业务计算放在service层，API处理参数及权限，Vue显示结果、原候选、种子、实际判断文字和排除原因。财务系统不在本批范围。

## 已接入的原程序和入口

| 原对象 | 新实现 | 页面位置 |
|---|---|---|
| Sp_CreateShiftAndClassDetail | 最新配置、周期累计、上一循环种子、换版、跨日四段；预览、生成、替换留档、撤回 | 基础信息原表p_ShiftArrange |
| Sp_GetShiftAndClass3 | 同日四段时分判断、后段覆盖、机台部门班组匹配；缺日只自动生成一次365天 | p_ShiftArrange、p_Machine；p_ShiftArrangeDetail提供只读查询 |
| qry_ProcessMachine | 机型与员工名单、06近30天进缸状态、2026年以来最后复版审核、其他工位AA/NULL规则 | 生产工卡JobSheet“按原工序与人员查询可选机台” |
| Fn_Get_Machine | GX07非空机台TOP1；否则原工卡StereotypesName前三字符 | 生产工卡JobSheet“查询原进缸机台及全部候选” |
| New_StringSplit | 原分号名单调用的空段、去空格和末尾分号规则 | 机台选择service内部 |

共13项页面动作绑定（含复用的办理事实动作），在现有模型上实现，无新增模型和字段迁移。原有665个ERP模型、554个原表模型、11,416个原字段及旧erpID保持；新生成日历的旧erpID为空，原ID由旧算法计算。

## 生成、替换与撤回

- 只读查询不创建日历；“补日历并查询”按原过程尝试一次365天，不保证覆盖任意遥远日期。
- 换版原DELETE范围改成活动日历替换留档；原值和原来源保留。零、负数、NULL生成天数仍执行原换版范围判断。
- 日历操作共用配置行锁；新行、替换原行和原值快照登记在已有办理事实中。撤回恢复原活动范围，新生成行也留档，不覆盖后续修改或颠倒跨入口生成依赖。
- 原计算错误在预览逐条明示；办理使用事务，不能留下只删未生或半批日历。异常配置、原行和不能计算原因仍能查询。
- 机台筛选返回可选列表，进缸提取返回另一套原标量结果；不把查询自动写成现场已选择或实际报工。

## 真实来源核对

旧库核验仅用SELECT、变量赋值SELECT、只读CTE及已确认只读的Fn_Get_Machine函数。**没有执行会写日历的两个排班过程**；其原定义与当前证据快照逐字核对。

| 项目 | 结果 |
|---|---|
| 原定义 | 5个程序/函数定义一致，SHA-256见JSON |
| 循环配置 | 12行、13字段与开发历史原表一致 |
| 日历明细 | 1,460行、15字段一致；2022-09-07至2026-09-05，无重复日期 |
| 从配置重算已有日历 | 从空明细起算1,460行，全部15个原字段与旧日历一致；仅内存计算 |
| 班组选择 | 120机台×12时刻=1,440组；117条结果与独立只读SQL一致 |
| 工序机台选择 | 8组真实参数，结果分别3/7/0/13/0/13/11/0行，共47行一致 |
| 进缸机台 | 6张真实工卡结果一致 |
| SQL边界探针 | RIGHT得到59:59、负余数-1、空整数0、NULL名称PATINDEX、NULL%0、DATETIME跨日舍入已核实 |
| 下一批日历预览 | 原ID1461～1825，2026-09-06至2027-09-05，共365行；未写入开发历史日历 |
| 运行接口 | 33项HTTP检查、13项动作绑定与权限存在；日历明细仍1,460行 |

本批没有重复导入旧数据。读取的是此前已承接的开发历史原表，并与当前旧库只读结果对照。生成/替换/撤回只在隔离测试库运行；运行服务的补日历查询核对选用已存在日期，不触发生成。
