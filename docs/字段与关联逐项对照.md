## 明确关联变化与保留

| 关联 | 核对结果 | 后续影响 |
| --- | --- | --- |
| Users.dept / Dept.parent | 两版 PROTECT / CASCADE 对应 | 删除有用户的部门仍保护；子部门无阻挡时级联。必须用真实关联数据验，不只空部门 |
| Users.role / Users.post | 多对多用途对应 | 授权成员增删仅操作当前角色；岗位多值模板另验 |
| Menu.parent / MenuButton.menu / MenuField.menu | 原/现 CASCADE | 删除菜单会影响按钮、字段、角色授权；动态路由/旧标签同步另见 F07、F08、F21 |
| Role → 菜单/按钮/字段、自定义部门 | 关系用途和删除声明对应 | 多角色并集、按按钮范围、字段授权需组合验；只读子页 F18 |
| Dictionary.parent | 原/现 PROTECT | 子项存在时删除根受保护；公开父状态不同见 C12 |
| Area.pcode | 原 to_field=code，现 code 即 pk | 功能仍为父区域码，数据/旧 FK 属性协议不同，不能按数值 id 转换 |
| SystemConfig.parent | 原/现 CASCADE | 组内保存/删除在事务；关联键、特殊动作 F04/F05 |
| MessageCenter.target_user | 原 through=接收表；现为指定目标 M2M | 明确方案 C14；实际接收者读 MessageCenterTargetUser，不能用指定目标冒充实际全部收件者 |
| MessageCenterTargetUser.users/messagecenter | 原/现 CASCADE | 用户/消息删除应移除接收记录；删除后的通知计数闭环仍需专项验 |
| CoreModel.creator | 原/现 SET_NULL | 创建人删后审计保留记录、创建人为空 |
| CoreModel.modifier/dept_belong | 原字符串，现外键 SET_NULL | 删除用户/部门后原字符串身份与当前空关联不同，属于 C20；历史迁移不能伪造身份 |
| SoftDeleteModel | 原任意关联对象调用软删，现仅软删 CASCADE | 不复制旧 TypeError；独立插件软删图仍需验 |
