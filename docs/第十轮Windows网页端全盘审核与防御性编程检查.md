## 4. 防御性编程检查：明确回答

**现有项目仍残留一处已确认的额外限制：用户名字符校验。不能回答“已经完全没有”。** 它由继承 Django 字段带入，并非本轮新增；来源不改变它对功能的限制。第 2 节 TW-DP03 优先移除，不通过逐接口白名单放行补丁处理。

本轮检查了当前 Python 的 39 个 try/raise/assert 候选节点、前端校验/切片/失败处理以及模型和继承字段。39 个是语法节点数量，嵌套 try/raise 可能重复出现，不是 39 处防御性编程。

| 代码类型 | 判断 |
| --- | --- |
| 认证、验证码、旧密码、密码确认、授权 | 对应已有功能；不因禁止防御性编程而移除真实权限链 |
| max_length、必要类型、唯一/FK、条件必填 | 逐项看原契约/模型用途，不能一概称“正常模型规则”而跳过比较；用户名继承规则就是反例 |
| xlsx 后缀、有效工作簿、表头、行字段错误 | 仅 xlsx 是明确要求；模板结构和具体错误定位是导入功能本身，没有新增行数、文件大小或批次数量封顶 |
| 导出 try/except Exception、任务失败 | 关闭临时资源/记录任务失败后重新 raise；不是吞异常/返回假成功 |
| SQLite 关联分批 | 遵循真实数据库参数容量，最终返回完整数据；不是给业务 limit 设置任意上限 |
| 文件页大小 10、图标每页 60 | 分页显示规模，不是禁止更多数据。文件选择器缺少调节入口仍是 UI 差异，列为整改 |
| 主键关联改名的已访问集合 | 避免同一关联重复改名，服务于真实关系图；不是禁止业务主键修改 |
| Role.admin/未实现登录方式标签 | 额外内容，不把它包装成必要防御；进入收敛复核，不添加更多占位功能 |

本次没有给产品添加限制、兼容兜底、吞异常、重试或新功能。不能凭上述检查证明所有第三方库内部行为都没有限制，也不能仅搜索 raise 就作出保证。
