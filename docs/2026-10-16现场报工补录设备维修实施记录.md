# 现场报工、补录与机台设备业务实施记录

第十九批；2026-10-15开始核对，2026-10-16完成；分支：feature/erp-seven-module-models。沿用 Django + Vue3，财务系统暂不开发。

## 本批实际实现

| 业务 | 服务与页面行为 | 原依据 |
|---|---|---|
| 工卡现场记录 | 工卡查询正式报工、工步及独立补录；选择原入口新增染色刷卡、刷卡产量补录、普通产量登记、独立染色补录 | DPWProcess、AddWProcessEdit、WProcessEdit、AddDyeWProcessStep及原入口默认值/主从关系 |
| 机台方案 | 按方案流水查询；没有直接方案时按机台取最新日期方案，返回原默认值、项目及结果类型 | sp_App_GetMachineCaseProject |
| 巡检 | 新增/修改表头，三串变更项目与方案左连接，生成项目、替换旧项目并留档；可逐步撤回 | sp_App_SaveInspectionLog |
| 保养 | 新增/修改表头和项目；保留修改不改保养日期、修改时间NULL等原行为；可撤回 | sp_App_SaveMachineCareRecords |
| 巡检/保养查询 | 已有项目优先，无项目且原参数为字面Y时从指定方案带出 | 两个BySheetSeries过程的项目部分；原表头仍由完整原模型展示 |
| 报修 | 按原APP保存检查创建/修改、机台部门与经营单位赋值、附件Guid绑定、创建/修改流转记录 | SaveMachineFaultBill、CheckMachineFaultBill |
| 维修办理 | 受理、指派、签到、取消签到、提交、退回、确认、拒绝、评价、评论、关闭、恢复、重新提交 | 八个sp_App_FalutAction过程，分别恢复原有效检查和回写 |
| 人员操作列表 | 普通版与含签到版分别查询；维修工、报修人、管理者、指派权和参数分别判断 | GetFaultActions、GetFaultActions2 |
| 配件与日志 | 提交时非负轮次最大值加1，仅更新原-1轮次配件；评论同时写流转与评论表；完整逐条查询 | Commit、Remark原过程 |
| 维修结果触发 | ResultID等于3或包含“已修”时回写结束时间，普通保存、审批和维修动作均接入 | MachineFault_Update |
| 反向办理 | 回写字段恢复，新增行与替换行留档，按本单办理顺序撤回；不覆盖后续已改变的业务字段 | 新系统明确提供的撤回能力，保留原字段和办理事实 |

本批25项页面动作绑定，计算和字段回写放在service层，API负责参数与数据权限。没有新增模型或字段迁移；所有原模型的旧erpID仍保留。新办理的记录不伪造旧erpID。

独立染色补录原模型当前位于打样目录，因此同时从生产工卡提供明确入口；没有擅自迁表，也没有把它转写成正式WProcessStep。原独立记录仍可完整查询和录入。
