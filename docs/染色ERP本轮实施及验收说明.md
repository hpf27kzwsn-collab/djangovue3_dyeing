# 染色ERP本轮实施及验收说明

更新：2026-10-13。技术基础为当前 Django + Vue3，沿用资料包的真实业务顺序；财务系统暂不实施。源字段以已采集的当前数据库结构及最新界面配置为证据。所有 659 个 ERP 模型都有额外字段【旧erpID】，不将新增字段冒称为旧物理字段。

本轮已新增独立质量管理，迁入原有检验、结果、处置和疵点模型；新增553个七模块原表模型，静态声明11,412个旧字段和158组明确主从关系。当前原表模型提供字段录入、主从入口和单据办理阶段，旧业务自动联动仍需逐条实现；全部历史业务记录尚未正式导入。详细实施和验证见《染色ERP七模块模型实施记录》。

2026-10-13目标更正：用户要求完整复刻六模块所有基础与业务流程、字段、关系和数据，低频、停用、空表及需解释原记录均不排除。本文是当前实施进度，不是最终范围完成声明；所选91表归档不代表原ERP完整业务表覆盖。此前“仅迁未结、停用仅查历史”的建议撤回。确定目标见《染色ERP后续开发方案》开头，现场问答G01～G05原答保留。

## 本轮已实现的软件范围

| 模块 | 已实现链条 |
|---|---|
| 基础信息 | 组织、人员班次、单位、主体角色、物料、仓库库位、机台工序、路线版本、色标准、包装及标签；读写权限和字段范围 |
| 销售管理 | 商业价格版本、订单确认和变更、交付实际出库与客户交付、退回收货、显式重开需求、投诉处理、完成/结案/重新办理 |
| 采购管理 | 申请、采购确认、分批待检收货、实际采购退货、净收货进度、按原因结案与重新办理 |
| 打样管理 | 收样、人员分配、多轮试验、送版和客户回复、最新轮次确板、配方与曲线版本冻结/复制 |
| 生产管理 | 订单分配、选定路线、工卡下达、组缸、人工排程和改排、配方采用、计划料单、实称与净领用、实际开完工/中止、更正、检验及处置、返修复检、生产完成和结案 |
| 仓储管理 | 货权批次库存、实际收发、待检放行、半成品产出、包装净重和细码、成品分批入库、调拨、盘点、质量调整、冲销、投入产出追溯、标签请求和人工结果确认 |

正常实物链为实际领料→松筒→路线所选装缸/染色及可选洗水、脱水、烘干、络筒、后纺→实际终检及数量放行→包装→工卡生产完成→成品收货→实际出库→客户交付。所选可选工序只有在明确允许时才能跳过；依赖仍以实际前置完工为准。返修建立独立路线和真实执行，承接原需求，不新增重复订单需求。

生产计划、采用剂量、实称、领料、工序实绩、包装及库存数量分别保存。实际记录缺失不拿计划填充；明确零与 NULL 分开。生产完工、更正、检验判定和谱系确认都不会自行产生第二笔库存。

## 关键数量和状态口径

- 同缸只记录一次物理执行；成员实绩合计等于整缸实绩。整缸更正同一事务保存全部成员及整缸历史，原实际量和原时间保留。
- 机台实际占用核对有效开完工区间；中止保留已开工时段且不生成产量，下一轮使用新轮次。
- 料单计划来源为当前采用快照，实称必须明确实测数量、单位、员工及时间。已采用的称量须先处理实际领料再取消采用。
- 检验须有真实范围和计量单位。终检/复检采用当前路线包装前最后实际产出；不合格普通放行拒绝，实际让步、降级和返修分别记录。
- 包装净重按实称毛重减筒皮和外包装皮重，或明确固定单粒质量乘实际粒数；各参数缺失保持未记录，采用参数及来源实绩冻结在快照。
- 包装采用的质量处置合计须等于净重，累计包装不能超过本轮真实产出或有效放行量；订单分配按对应质量、长度或计数维度核对。
- 原工卡和返修包装共用原订单需求上限。完成后显式释放未形成包装的需求时记录数量和原因，原计划不改写。
- 销售实际交付量来自已过账出库及客户交付事实；退回先入待检库存，是否重新打开订单需求必须明确。订单提前结案保留原订货量和未交付量，不能冒称足量完成。
- 谱系完整引用真实投入出库和实际产出收货，不新增库存流水。源收发更正前先取消谱系采用，保留原谱系。

## 查询与现场入口

已有 12 类跨模块查询及全部结果 CSV 导出：订单交付、工卡实际进度、计划/实称/净领用、检验及处置、准确维度库存、包装收发、价格版本、最新打样轮次、采购净收货、排程与机台执行、返修复检、投入产出追溯。

查询读取各来源的查询权限、字段权限和数据范围，关联名称也须有来源授权。不同维度分别展示，不混算公斤、米、粒。分页总数按主单/主对象统计，一张主单可展示多条明细；导出遍历全部主对象页。

扫码入口支持员工卡号/编码、工卡号、包装条码的精确识别；重复结果全部展示，由操作人员明确选择。识别本身不制造报工。标签保存模板版本、实际包装和请求快照；请求、失败、成功和重打分开，成功由真实人工确认。

资料包未提供当前现场秤、刷卡机、机台控制器和打印机的可执行协议及实际连接参数。本轮已提供人工/扫码办理和结果记录入口，未声明真实硬件已接通。后续设备接入必须用设备的真实回传验证，不能把请求发出当作实际执行成功。

## 全量旧资料、导入和对照

完整业务来源已提取 91 表、9,055,094 行、3,712 字段，共 8.72 GB。源文件含原主键、行号、完整原值、字段类型及摘要；来源归档页面可以分页读取任意原行。见《旧来源表提取核对清单》。原业务日志仍保留完整合并文件，共 1,516,057 行；日志说明访问和操作，不用来填补实际单据事实。

目前已明确采用的主档映射为：734 条非财务字典、33 个班次、274 位员工、182 个往来单位、120 台机台，共 1,343 条。明确的员工班次、主体上级、业务员、主体类别和字典上级按同批次唯一代码第二遍匹配；其余原关联保留完整来源及核对事项。重复执行保留原映射和已维护的新值，不覆盖人工改动。

旧新对照逐字段展示完整原值、当前新值和转换含义，保留原复合主键。每张来源表、每个导入对象、未采用字段和关联均可查。归档路径按项目根目录保存相对位置；复制项目和资料文件后按新根目录定位。

本轮实际数据验证后的模型修订：字典排序、班次/主体/员工/机台名称及机台容量描述保留旧 NULL；机台编号取消不符合旧数据的全局唯一限制。新机台工厂关联暂允许未确认，原停用标志 NULL 原样保留；机台进入实际排程前仍须明确工厂、适用工序和启用状态。不存在从缺失值推定启用的规则。

完整归档不等于全部历史单据已进入新业务模型。组织代码、物料单位、部分状态含义和真实切换库存范围尚缺可证明的对应，历史单据目前由原表完整展示；不可在这些对应未明确时调用新动作补出不存在的称量、放行或库存。所有已证明字段可独立对照；未采用关系保留处理事项。历史重建流水与切换期初必须选定各自范围，不能重复形成库存。

## 本轮验证和运行

实际数据库已应用 45 个 ERP 迁移，并登记完整来源及 1,343 条明确主档。完整正式迁移回归 236 项：231 项通过、5 项 SQLite 并发跳过；对应五项实际行锁测试已在独立 PostgreSQL 通过，最终 PostgreSQL 14 项和最后补项 5 项、8 项验证也全部通过。前端类型检查和正式构建通过，157 项实际接口/资源检查通过，服务运行于 `http://127.0.0.1:8000`。详细证据见《业务功能逐批实施记录》。

业务测试使用独立数据库，未向实际项目插入演示业务单据。实际登录仍按既有首次改密码流程办理；现场整条操作链、完整外协单据及真实设备回传另行按资料包代表样本验收。目前91表包含半成品收发来源，但没有涵盖完整独立外协申请主从等原表；这些需补提取和完整复刻，不能称全部外协来源已归档。

## 继续开发的实际顺序（2026-10-13更正）

1. 按旧目录、最新字段配置、原表、业务程序和单据流程建立完整六模块覆盖清单，列出目前遗漏的表、字段、关系、计算及入口；包括坯布、定型、外协和低频/停用功能，91表不作为上限。
2. 核对现有模型与动作中未忠实复刻的规则，包含包装条码身份、空单位、负数、旧单节点路线、质量关口、机台能力及全部单据草稿/确认/审核要求。能核实的直接落实，真正无法复刻的列明差异和方案交用户裁定。
3. 补齐所有基础及业务模型与对应流程，再逐模型试导入和对照全部历史数据。保留原值、原键和主从关系；异常或未解释的原记录也要被新系统承接，不仅留在原文件。
4. 完整历史核对后，单独确定正式抽取时点、实际未结接续和库存采用方式，避免历史流水与期初重复计量；不因此取消历史记录的导入。
5. 旧接口业务资料、任务和结果同样列入完整复刻；实际设备连接及真实命令/回传按现场协议联调，软件覆盖与实物设备上线分别验收。

上述是全部完成目标的依赖顺序，不划分由开发者自行缩减的首期范围。所有实际未完成项持续列清，不以归档或通过局部测试代替全范围完成。
