# 包装替换新增、投坯排序配对及撤回实施记录

日期：2026-10-15。分支：feature/erp-seven-module-models。依据2026-10-14已核验结构与原程序定义、本项目第八批后的剩余开发顺序；本批继续包装历史链，不重复导入旧数据。

## 实际实现

| 所属模块/页面 | 新增操作 | 服务及实际影响 |
|---|---|---|
| 仓储 / RecordYield | 预览同卡同卷包装替换 | 列出全部活动匹配记录及旧erpID |
| 仓储 / RecordYield | 同卡同卷替换新增包装 | 原匹配行留档，新Guid、新包装条码、原20参数及最新必填CheckNo；已有实际收发独立保留 |
| 仓储 / RecordYield | 撤回本次包装替换 | 新包装留档，恢复被替换原行及本次GX98/当前工序前值；不删除历史或实际流水 |
| 生产 / JobSheet | 预览包装与投坯排序配对 | 原文本排序、流水分组、全部条码连接候选和未匹配明细 |
| 生产 / JobSheet | 按原排序采用投坯细码 | 回写GrayWeight/GrayBarCode，保存候选、实际选择及每条前后值 |
| 生产 / JobSheet | 撤回本次包装排序配对 | 恢复各包装原字段及前次采用事实 |
| 仓储 / RecordYield | 撤回明确投坯采用 | 单条更正按前值撤回；可随后撤回前次批量配对 |

新增7个动作，均注册页面元数据和按钮权限。替换表单预填所选原记录参数，保留NULL与原精度；接口仅处理参数、权限及结果，计算、事务、来源追溯与逆向位于source_package_operations/source_packaging_flow等service。原模型及字段没有迁移，仍为662个ERP模型，全部具有【旧erpID】。

## 与原业务及现有链条的关系

RecordYield_Add按工卡号与卷号替换全部命中行，不能只取第一条或以同码重复为由丢弃来源。新系统用活动状态代替原DELETE，普通原表列表完整保留旧行。包装汇总、后续入库、排序配对和执行整链采用活动记录；条码自动编号的已用号码仍查全部留档行，不复用因替换退出活动范围的旧号码。

替换前已有实际入库不随包装替换重做；新包装另生成实际入库时必须使用实际数量和对应办理动作。撤回替换前核对新增入库引用、替换后字段及本次进度变化；有后续办理时先撤回该办理，避免覆盖已发生事实。工卡整链继续沿全部替换层级寻找原包装明确生成的入库，入库工卡号缺失仍能按该来源找到实际流水。

排序配对保留重复条码、同流水多表头、相同排序键、NULL和负值。所有候选可见，多候选按稳定顺序采用最后一条；未匹配行原字段不变，未采用投坯另列说明。批量配对与明确单条采用各有前后事实，按办理先后倒序撤回。未指定的旧排序、三位序号溢出及当前CheckNo漏列差异详见异常E56～E58。
