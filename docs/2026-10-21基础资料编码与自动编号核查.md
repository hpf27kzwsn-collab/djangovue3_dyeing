# 基础资料编码与自动编号核查

日期：2026-10-21。

旧ERP的大部分基础主档有自身业务编码，部分关系表只保存父资料代码与明细号，部分考勤配置采用自增主键。新系统原形模型已保留对应旧字段，没有必要给所有表再造一个统一Code字段。但当前自动编号并未全部可用，不能把“有字段、有规则”当作“已完整复刻”。

## 与上一轮导入包说明的修正

上一轮“客户可以自动编号”仅在尚未承接旧往来单位的验证库测试通过。此次带完整旧资料复测，客户自动编号失败：旧客户CustomerID是000、001等数字串，旧供应商是G001、G002等合法字母编码；当前取号扫描没有保持旧客户/供应商分类范围，把两类编码放在一起转整数。旧编码本身没有因此变成异常，不能删除字母或跳过这些资料。

供应商不仅有CustomerID的编号规则，还在旧配置中有NUM的AutoAdd规则，实际数据库列名为Num。当前构建规则按大小写精确比对，漏掉这一条；原CustomerID又由表达式[NUM]回写。当前手填CustomerID或明确填写Num能保存，不能据此认为留空自动链已还原。

旧资料文件已经有完整原编码，使用“历史基础资料原值承接”不经过这些新编号逻辑，前一轮原值导入验证结论不变。准备新增资料时，部门、客户、供应商、机物料及自动失败的分类应先明确填写编码。本轮没有修改业务代码、模型、编号规则或你正在准备的xlsx，未正式导入数据。

## 编码 主键 与引用码

1. 业务编码是DeptID、EmpID、CustomerID、StuffID、Code等用于识别某项资料的原字段。名称相同不表示编码相同，字母和前导零均保留。
2. 原自增主键如USERINFO.USERID用于原表行身份，不等于员工工号。新系统自己的id也不替代EmpID、CustomerID等业务码。
3. 明细中的CustomerID、MachineID、ProcessID经常是引用父资料；RowNo、DetailNo、SortNo是明细号或排序值，不能给每张关系表都再造一个独立“主档编码”。
4. 旧表没有独立编码的来源，如部分比例/关系配置，仍按原字段录入。没有为它们统一新增Code，也没有新增旧erpID。p_Gray原有OldGrayID等字段属于旧表原字段，不是后加的旧erpID。
5. 普通新增时，非自增编码可在规则允许的字段中明确填写；传入空串/NULL不等于不传字段。页面启用自动编号会去掉空的生成字段；手填时可关闭“使用自动编号和默认值”，若旧表单规则锁定字段，另需核对“按表单规则编辑”开关。手工验证是接口保存验证，没有在本轮逐个浏览器表单验收。Excel真正留白也不等于写#NULL或#EMPTY。原自增字段由服务分配，历史方式才保留原值。

本轮完成字段/规则核查及列明的开发验证，不表示旧原形主档已经自动采用到整理主档，也不表示全ERP历史对账或现场验收完成。财务、打印及原35项查询继续暂缓。

## 已发现的编号差异

| 差异 | 当前结果 | 后续应核对的内容 |
| --- | --- | --- |
| 客户与供应商取号范围 | 客户被供应商合法G前缀阻断；供应商同样失败 | 旧入口SQL的CustKindID范围、实际前缀、旧Num生成及回写顺序 |
| 供应商NUM规则漏接 | 旧字段配置NUM与实际列Num的大小写不同，旧规则未进入生成清单 | 按SQL Server标识符规则对应到原列，复核GenerateTime=2与CustomerID=[NUM] |
| 部门与部分班组DateCode | 部门生成11字符而原字段最多10；部分班组12字符而最多10 | 原日期格式、YearCode默认含义、后缀位数和生成时机；不能截断旧码 |
| 员工编码长度 | 旧配置HF+FixedLength4，现实现至少6位，实测HF001687 | 恢复旧位数语义；另一个无HF前缀入口单独核对，不能混为一个入口 |
| 机物料、包装纸筒及部分分类 | 合法A01/B01/RMB等被纯数字算法拒绝 | 各原入口的前缀及尾号规则；未声明自动的枚举仍手工维护，不能删除旧字母 |
| 染化料编码与科目码混淆 | p_Stuff只有AccSubjectID被配置自动号，StuffID不在其中 | 物料码、财务关联码分别呈现，不因科目自动号就判StuffID已自动生成 |
| 明细引用码与自身编号混淆 | 某些明细的ID/CustomerID编号配置实际涉及父资料 | 按表头来源继承和明细编号各自验证，不能简单全表套号 |

自动失败并不构成跳过原数据的理由。后续修复应保留全部原编码、重复行和停用来源，按入口复刻编号范围与公式，再分别验证空库新增、带旧数据新增和明确手填三种情况。

## 依据

- 旧库sys.columns、sys.indexes与sys.index_columns：原字段、长度、主键和自增属性。
- 旧库s_DataTable与s_DataTableField：具体入口SQL范围、编号规则、前缀、位数、生成时机和表达式；只读取文本，没有执行存储SQL。
- 当前foundation_catalog、各原形模型SOURCE_FIELDS/SOURCE_KEY/SOURCE_IDENTITIES，以及source_entry_rules：入口及字段对应。
- source_numbers、source_entry_services、source_sequences、source_phase6_local_values和实际新增接口：取号、原自增分配、供应商NUM联动。
- 独立验证库209组实际新增及回滚核对；旧码示例来自2026-10-21只读提取，不使用新生成的值冒充旧码。
