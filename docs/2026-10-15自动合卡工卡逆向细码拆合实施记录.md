# 自动合卡、工卡逆向与坯料细码拆合实施记录

> 2026-10-16 来源设计更新：当前及后续开发取消额外【旧erpID】，保留旧表原键字段，使用来源批次/提取行及既有来源映射追溯。本文早期实施和验证记录中的旧字段描述属于当时状态，不再作为当前模型要求。以[原键字段与来源追溯规范](原键字段与来源追溯规范.md)为准。

日期：2026-10-15。分支：`feature/erp-seven-module-models`。技术基础为当前Django + Vue3；本批沿用最新553个原表模型，无新增物理字段或迁移。全部ERP模型继续包含【旧erpID】。

## 本批可办理内容

| 模块/原表 | 页面操作 | 服务及实际结果 |
|---|---|---|
| 生产 / JobProcess | 预览原自动合卡选路；按原称料/排程自动同步合卡 | source_auto_combine：G-06/G-07正反成员、排程卡号:工序号、时间/延迟筛选、候选和未匹配片段明示；source_job_flow写0/1/2时间、状态、机台及原下一工序 |
| 生产 / JobSheet | 撤回本次拆合计划 | source_card_reverse：拆卡恢复来源前值；合卡量归零留档；可明确仅撤回计划，实际单据继续保留 |
| 生产 / JobCombineOrder | 撤回本次分配转移 | 恢复来源转移前数量、目标量归零；连续转移按逆序恢复 |
| 生产 / JobCombine | 撤回本次原合卡关系采用 | 采用量归零留档，原孤立关系继续保存 |
| 仓储 / GrayInRecord | 拆分本条坯料细码；合并选定坯料细码并保留参与行 | source_gray_split_merge：出库前数量、卷号和条码、收料明细及流水、可选工卡投坯和分配回写 |
| 生产 / JobGrayRecord | 同上 | 出库后细码、Kg/GUnit、JobAssign与工卡重量后长度回写；不忽略旧空表对应业务 |
| 仓储 / GrayRecordCutLogs | 查看拆合结果或原日志；撤回本次细码拆合 | 原日志照常可看；本次有完整前值的操作逐字段恢复；新拆分结果留档退出活动汇总 |

上述页面同时显示接续事实，可查撤回状态、消耗状态及关联日志ID。拆合结果弹窗显示新建/合并结果记录ID和异常明细，中文列名便于查找。自动选路结果列出采用来源、全部候选、原片段和未匹配原因。

操作参数、权限和响应位于source_api；计算、选择、回写、事务与审计位于service。动作元数据维护在tools/legacy_models/continuation_actions.py，经原生成器生成，不手改一次性页面注册。未新增万能规则引擎、异常吞掉或默认成功分支。

## 数量、来源与逆向

原参与细码和旧erpID保留。合并消耗行、撤回后的拆分结果仍可在原表查看，但不再次计入活动细码汇总；收料公式、单位/领用回写、库位转移及包装采用使用同一活动状态。新卡不复制来源空NewSheetNo，按旧入口生成新编号并写入SheetNo，后续实际单据可以关联。

数量采用每个最新旧字段自己的精度。NULL和负值保留，超拆、已部分领用和已有成品引用等差异可登记后继续明确调整，既有实际单据不自动改写。旧合并DELETE替换为参与行留档，日志摘要之外另存完整来源和逐字段前后值。

撤回按逐字段前值执行；若后续改过本次字段或拆分结果已参与下一次合并，需要先撤回后续动作，失败整体回滚。普通删除不能绕过本次办理事实。仅撤回计划模式保留已称料、已报工、已收发等实际单据，未宣称实现全套库存自动逆向。
