## 明确的实现选择

- 部门编码仅非空时唯一，允许多条空编码；保留原业务唯一含义并避免空值被不必要限制。已有非空重复编码需先处理才能应用迁移，不自动删改业务记录。
- Menu 路由/图标等字符串以空字符串表达未填写；配置的对象/数组采用明确 JSON 类型；接收已读为二态布尔；本地附件由实际上传创建，不制造空二进制记录。下载状态/大小为数字，日志 IP/请求响应 JSON 使用当前字段类型，部分空文本以空字符串表达。不是旧序列化值逐项兼容协议。
- 已有更宽字符串长度继续保留；恢复确认影响实际业务输入的可空字段。业务保护删除、唯一标识、授权和字段类型属于功能规则，没有新增任意业务数量、大小、密码复杂度或兜底重试限制。
- 接收表历史审计时间使用迁移时刻，未知创建人保持空，不伪造历史。新投递和阅读正常记录请求操作人。
- 新生成按钮不自动授予既有角色；菜单前缀与实际 API 资源分开。角色需按现有授权页面勾选新增动作。
- 旧 get_relation_info 等辅助接口以已有受授权的关系查询/配置分组接口替代；旧全局请求上下文以显式 request 替代。AdminPermission 提供超级管理员或启用 admin 角色的独立权限类，不替换正常业务 ApiPermission。
- 字段权限目录仍按模型类名识别，不同应用同名模型的歧义属于原有继承边界；自动匹配入口仍遍历普通模型字段，init_data 会登记多对多，二者没有宣称完全等价。旧实例 DATA/DICT_DATA 等辅助方法没有逐个保留，扩展接入使用 ORM/serializer 新契约。
- XLSX 继续使用已实施的 openpyxl 写入/读入逻辑；本次没有恢复旧模板引擎、xls 或公式计算。字典/文件选择仍沿用既定鉴权契约，不新增匿名旁路。
- 图标使用当前 Element Plus/Iconify 名称，新组件不承诺旧阿里图标 CSS 类名直接兼容。静态菜单在源码配置，默认后台模式。
