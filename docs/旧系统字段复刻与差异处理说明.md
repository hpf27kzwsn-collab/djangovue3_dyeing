## 2. 字段复刻的执行规则

| 项目 | 执行规则 |
| --- | --- |
| 已明确的事实含义 | 按当前旧入口复刻，不按英文列名猜中文业务含义；品牌、用途、特殊事项等独立保留 |
| 直接对应的文本 | 按旧 varchar/nvarchar/char/nchar 声明长度保存；max、text/ntext 使用 TextField；nvarchar 字节长度换算为字符长度 |
| 原文本空值 | 可直接对应的可空文本分别保留 NULL 和空串；没有旧列的新文本按明确的新业务定义处理 |
| 原布尔标志 | 保留 NULL、否、是三种情况；没有旧默认的可空标志不在模型中默认补成 True/False |
| 原值 Decimal | 可以直接原值保存的剂量、色度、幅宽、价格等按旧 precision/scale 定义，不把 decimal 的存储字节数当成精度 |
| 发生时间 | 保留旧 datetime 的完整日期时间，按上海时间解释；新系统审计时间与旧业务时间分开 |
| 业务代码及主键 | 保留文本、前导零及真实复合键，建立新 ID 映射；不通过名称或同号猜关联 |
| 页面设置 | 按对应旧页面记录的标题、编辑器、必填、只读、显示精度及表达式还原；配置未填写不等于 False 或 0 |
| 旧默认表达式 | 数据库默认、界面新建默认、已有历史空值分别处理；新建默认不能反向填入旧缺失事实 |
| 旧计算字段 | 复刻有依据的公式和计算口径；明确属于汇总的量由来源计算，不再作为第二套可写事实 |

代码仍使用明确的 Django 英文字段名和新内部外键。关联、版本及快照无法与旧物理列一一同形时，采用下一节的合理方案并登记差异。页面标题和说明能够保留旧术语，不要求把旧字符串键强行存进新外键。

## 3. 已实际修正的主要差异

| 项目 | 旧系统依据 | 已落地处理 |
| --- | --- | --- |
| 直接字段标题 | 当前主入口/编辑入口具有一致标题 | 调整 138 项标题；关系、枚举、启用取反及明显业务归一化标题单独记录 |
| 直接文本定义 | 单一旧字符列、长度及可空性明确 | 核对并修订 110 项文本定义；含长度、长短文本类型和 NULL/空串区别 |
| 原值小数定义 | 直接原值使用旧 decimal，未涉及数量归一化 | 30 项按旧 precision/scale 保存；单位转换、计算快照等继续保留明确的扩展精度 |
| 员工进厂、离职 | `h_Employee.InDate/OutDate` 是 datetime，界面采用 DateTime 编辑器 | `Employee.joined_on/left_on` 改为 DateTimeField，不截断时间 |
| 销售订单品牌 | `OrderMain.Linker` 当前编辑标题为“品牌” | 原 `contact_name` 改为 `brand_name`，保留原品牌文本；联系信息仍由 `LinkerInfo` 单独保存 |
| 订单明细用途 | `OrderColor.ColorRemarks` 当前标题为“用途” | 原 `quality_requirements` 改为 `intended_use`，不缩窄为质量要求 |
| 订单特殊事项 | `OrderColor.Atte` 当前标题为“特殊事项” | 原 `packaging_requirements` 改为 `special_requirements`，保留完整事项 |
| 染色与交货日期 | `OrderColor.DlvDate` 当前标题为“染色日期”；`FinalDlvDate` 为“协议交货日期” | 原 `due_at` 改为 `dyeing_due_at`；`final_due_at` 单独保存协议交货日期 |
| 工卡结案 | `JobSheet.FinishDate` 当前标题为“结案日期” | 新增 `WorkCard.closed_at` 承接旧结案时间；`completed_at` 只表达新系统实际生产完成时间 |
| 旧可空业务标志 | 以下 12 项源列允许 NULL，且无数据库默认 | 改为可空且不设布尔模型默认，保留旧未知情况 |

12 项标志：`Employee.is_active`、`Party.is_active`、`BusinessChoice.is_active`、`Material.batch_managed`、`Material.is_active`、`Machine.is_active`、`PackagingSpecification.is_active`、`SalesOrder.is_urgent`、`SalesOrderLine.is_closed`、`CommercialPriceLine.is_confirmed`、`WorkCard.is_urgent`、`WorkCardOrderAllocation.is_primary`。

启用字段取反时：旧停用/离职为是 → 新启用为否；旧为否 → 新启用为是；旧为 NULL → 新仍为 NULL。不同物料家族的旧停用字段分别映射。`CommercialPriceLine.is_confirmed` 按已核实的 0/1 标志解释，冲突表达式不用于反推确认事实。

已采用独立修订迁移：4 个英文名变更使用 RenameField，随后修改字段设置；工卡增加独立结案字段。原有初始迁移没有重写。

## 4. 无法直接同形复刻的合理方案

| 差异 | 当前合理方案 | 后续实现要求 |
| --- | --- | --- |
| 多旧表合为同一主档 | 主体、物料、商业价格等使用统一模型；通过旧表名和完整键区分来源 | 保留各入口对应标题和来源，不能因为同号合并不同旧对象 |
| 一旧行拆为多个对象 | 联系地址、配方版本、采用阶段等各自保存明确事实 | 可以在不同新对象记录同一旧来源身份，父子关系由新外键维护 |
| 旧代码关系变新外键 | 通过确定的来源键映射到新 ID | 没有完整键的关系不按同色号、名称或最后一条记录猜联 |
| 旧参数横向槽位 | `JobProcess` 的 01～30 槽位按参数行归一化 | 槽位及节点来源完整保留，实际值不能冒充已确定轮次的报工 |
| float/real 改精确业务量 | 使用明确的 Decimal 定义，并保留原浮点值归档 | 实际导入前核对量程和舍入；不能称这种转换为任意浮点无损转换 |
| 数量单位或计算口径改变 | 基本库存量、辅助量、计划量、实测量分别保存，数量换算及计算快照保留需要的扩展精度 | 按已经明确的单位换算，不从旧单位全空字段自动补 kg |
| 新工作流状态 | 沿用当前明确的新枚举，旧整数码逐表映射 | 未确认的旧码不直接变成新系统可执行状态；旧空值不按新建草稿默认覆盖 |
| 干料百分数与 g/L | 新业务显式选择干料质量百分比或浴液浓度，并填写计算基准 | 旧 0/1 只证明百分数/g/L，不能自动证明旧百分数一定采用干料质量基准 |
| 图案 image | `YarnSpecification.pattern_file` 关联现有附件资源 | 提取原图片保存为附件，不改成描述文字 |
| 旧字典变结构化对象 | 单位、仓库、工作中心、包装、标签等使用各自模型 | 字典 NumValue 不能统一解释为 kg；字段值与命名空间一起解释 |
| 包装净重 | 保留明确的扣皮重或固定单粒质量方法与采用结果 | 不通过物料编码位置决定公式，未核实附加重量不加进净重 |
| 旧累计及库存余额 | 通过已生效来源和流水形成查询结果，余额由库存服务维护 | 保留旧结果供对账，不能把累计量和来源量重复入账 |
| 负数及重复条码 | 小数保留，负记录按真实更正/逆向来源处理，条码结合完整来源核对 | 不截整数、不取绝对值、不仅凭条码合并不同记录 |
| 配置冲突或含义未明 | 在对照表保留全部候选，当前使用明确的新含义与生成动作 | 未核实的旧值保留来源档，不写入不适用字段，不设置隐藏默认 |

没有独立旧物理列的 408 个专属字段均逐项列出当前定义和生成/赋值理由，不能标成旧字段的直接复制。这包括新关系、版本、快照、动作时间和单据控制字段。

旧表的 3,712 项字段仍按实际去向区分直接/归一化映射、计算、公共审计、内部键和状态、旧来源保留及财务排除。**“旧来源保留”表示当前没有独立可写新字段，不能算作已实现复刻。** 本次合理安排是保留原始字段和来源，供旧系统只读查询及后续对应业务还原；其字段设置已完整列入逐项对照，能够核实的业务字段在对应功能接入时继续按旧定义落实，不静默丢弃。

## 5. 原键字段与来源对应（2026-10-16修订）

取消全部ERP模型额外的 `legacy_id`，不增加同义替代列。保留原表实际主键各列、真实自增列及业务编号的值、类型、前导零和原文本。当前原键以最新静态模型 SOURCE_KEY、SOURCE_FIELDS 及来源表结构为准；早期候选键不替代最新核验结果。

原表记录通过已有来源批次/提取行定位本次抽取的每一行；已转换主档通过既有 LegacyObjectMap 对应原表及完整原键。单键、联合键、重复原键及无键表均承接全部原行。跨批次不能按提取行号或相同条码认定为同一业务记录。

新建业务不设置历史批次。多个原记录派生一个新对象时，完整直接来源由已有映射及办理上下文保留，不任取第一行充当唯一原身份。归档副本的历史来源通过归档上下文识别，不混入原表的抽取行集合。

比较使用原键字段及全部原值；没有可靠键的记录保留重复次数。通用主档不能采用的异常记录仍完整保存在原表复刻模型，并给出具体采用差异。具体导入、对比、权限及升级要求见[原键字段与来源追溯规范](原键字段与来源追溯规范.md)。
