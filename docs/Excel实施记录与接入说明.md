## 使用方法与实际保存语义

新增：在对应页面下载“新增模板”，填写“数据”工作表中的中文业务列，再从“xlsx 导入”选择文件并提交。空行不新增记录，必填/default/唯一性继续由正常 serializer 处理。

更新：先按页面条件筛选，再下载“更新模板”。保留“更新主键(勿改)”，修改需要变更的内容；可以移动中文列、删除无需更新的业务列。上传含该主键表头的工作簿执行更新，每行按实际模型主键定位，主键不存在或不在修改范围时整文件回滚。

空白单元格不提交，更新保持原值；0 和 False 有效。重复主键按工作表顺序保存，后面的有效值覆盖前面的值。本轮没有添加特殊清空标记，清空字段使用现有编辑页面。错误不会跳过后伪报成功，也没有任意文件大小/行数/频次限制。

关系显示为“名称 [主键]”，重名对象通过主键区分；导入以主键匹配当前可用选项。多对多使用标准 CSV 分号编码，例如 `财务 [12];采购 [34]`；名称含分号/引号时按 CSV 引用，模板说明中的示例也用同一编码。单选下拉不等于多选；多对多填写文本，保持无宏 xlsx。

编号/手机/主键按文本保存，保留前导零；以等号开头的业务文本仍写成文本。日期时间按 Asia/Shanghai 展示，原生 Excel 日期时间经过 serializer 转为项目时区后存储。openpyxl 不计算公式，只读取 Excel/WPS 计算并保存的缓存结果；无缓存按空值语义处理。

用户新增和更新同步 dept_belong 为用户实际 dept，页面与 Excel 共用 UserSerializer。更新普通信息不提交密码，也不重新设置密码。没有批量重写已有历史用户归属记录；后续保存时会同步。消息通过 Excel 新增会执行正常接收人分发；更新同页面更新一样不自动重新发布。

普通导出使用查询字段权限；更新模板使用查询与更新字段权限交集，数据按当前查询与修改范围交集取得。导入重新按正常新增/修改权限和范围保存；当前筛选与 URL 部门/父项条件同样传到同步、异步及更新模板。

## 后续业务接入示例

现有 `docs/generated-example/post/views.py` 继承 ResourceViewSet，已经继承新增/更新模板、导入及同步/异步导出。模型登记、菜单/字段初始化及普通角色授权仍按原生成示例办理；仅创建一个 Python 类并不会自动完成这些注册。

最简单的接入使用模型 verbose_name、choices 和正常 serializer，自动得到列与类型。需要缩小模板业务列时，可以直接覆盖 excel_columns；以下在已有 PostViewSet 中添加，保留更新定位列：

```python
def excel_columns(self, mode, queryset=None):
    columns = super().excel_columns(mode, queryset)
    keys = {'__pk', 'name', 'code', 'sort', 'status'}
    if mode == 'export':
        keys.add('id')
    return [column for column in columns if column['key'] in keys]
```

这样复用已授权列和关系查询，不复制一套导入校验器。特殊标题或计算展示列在相应视图的 excel_columns/excel_rows 中直接表达。业务新增/修改逻辑优先放正常 serializer；若正常页面还有明确保存后的动作，覆盖 `excel_save(self, serializer, audit, mode)`，调用 super 保存后执行同一动作。消息分发是本项目已有实例，不创建新的插件工厂。

通用关系选项按 ENTITIES 中目标实体的 GET 范围取得；现有对象关联的值也保留在更新选项中。新业务涉及专用可选集合时，在自己的 excel_columns 中提供具体 options，不能只登记外键就宣称全部业务可选规则已自动满足。
