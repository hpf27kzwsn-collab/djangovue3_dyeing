# 框架扩展与组件接入

## 注册独立 Django 应用

在 `application/plugins.py` 的 APPS 登记 AppConfig，迁移后执行 init_data。非 system 模型自动取得 `app_label_modelname` 实体键、通用 API、元数据、菜单、按钮和字段目录；不再改 ENTITIES。专用接口仍可登记 URLS 或生成后扩展。

MODEL_EXCLUDE_APPS 排除整应用；AppConfig.exclude_models 按模型类名排除模型。目录排除同时用于字段目录、自动实体和配置关联表目录。

INITIALIZERS 登记种子函数的点分路径。函数自行以明确唯一键 get_or_create/update_or_create，异常正常抛出，整体事务回滚。

示例验证：

```powershell
cd backend
..\.venv\Scripts\python.exe manage.py test system.tests examples.catalogue --settings=application.example_settings
..\.venv\Scripts\python.exe manage.py generate_crud example_catalogue.Entry --settings=application.example_settings --output ../runtime/generated-example
```

示例设置只用于接入验证。正式启用自己的应用时仍登记 APPS，按实际模型生成迁移，再迁移和 init_data。重复 init_data 保留既有密码及用户已调整的授权；新增按钮不会自动扩大现有角色权限，需正常配置授权。

## 初始化 JSON

```powershell
..\.venv\Scripts\python.exe manage.py load_init_data system.Post ../my-posts.json --unique-fields code
```

输入为 init_data 导出的 JSON 数组。默认按实际主键定位，也可指定唯一字段；匹配已有对象时部分更新，其他行新增。保留输入主键，关系使用新框架的实际主键。`--reset` 明确清空该模型再导入；正常外键级联仍会发生。整个导入使用一个事务。

导入业务字段并按 `--user`（默认 superadmin）写操作审计，保留已有创建人/归属，不把旧审计时间作为当前操作时间。源 JSON 没有导出密码；新增用户使用已配置默认密码，既有用户密码保持。接收表、媒体二进制和任务结果不是业务 JSON 恢复替代品。

## ORM 审计与软删除

```python
Entry.objects.create(audit_request=request, code='a', name='示例')
Entry.objects.filter(code='a').update(audit_request=request, name='更新')
```

显式传入 request 才写当前操作人，更新同时写修改时间；不使用全局隐藏请求上下文。API 通过 serializer/audit 完成同一职责。Users 保留 Django UserManager 的 create_user/create_superuser，账户保存用 UserSerializer。

需要软删除的业务模型显式使用 SoftDeleteModel 和 SoftDeleteManager。objects 查询排除已删除，all_objects 用于明确查看全量。delete() 标记自身及同样采用软删除的 CASCADE 子模型，delete(soft_delete=False) 执行 Django 正常硬删除。系统管理表没有被整体改成软删除，也未添加新恢复界面。

## Windows 与服务接口

窗口/托盘都有启动、停止、打开、显示/恢复和退出入口；窗口展示进程状态及增量日志。就绪后打开平台。Windows 的无窗口子服务由 QProcess 结束；停止正在运行的任务会终止该进程。目录中 backend 仍是实际数据，升级前保留它。

桌面默认端口 8000，可用 DJANGO_PORT 为独立验收指定别的本地端口。REDIS_URL 可指定既有 Redis；验收副本使用 6390，正式仍 6389。不要让不同数据库的 worker 共用同一任务队列。

`/healthz` 表达服务存活，`/readiness` 读取当前 SQLite。任务结果启用 result_extended，让任务名称/参数/工作进程等现有字段实际保存；不回填已有结果。

## 第 14—18 批：实际字段配置入口

在模型应用的 AppConfig 配置运行时元数据，例如：

```python
class CatalogueConfig(AppConfig):
    name = 'examples.catalogue'
    label = 'example_catalogue'
    resource_options = {
        'Entry': {
            'fields': {'amount': {'title': '金额', 'column': {'minWidth': 180}}},
            'exclude_fields': ['internal_note'],
            'search_fields': ['name', 'owner__name'],
        },
    }
```

字段名按自己的实际模型填写。fields 可覆盖 title、kind、column、form；exclude_fields 只排除 UI 字段；serializer_exclude_fields 单独排除通用 API 字段；search_fields 为正常 ORM 查询路径。readonly 和字段授权仍生效，不能用配置打开未授权字段。Decimal 的 kind 为 decimal，以字符串提交避免前端浮点精度损失；Time 为 time。关联字段取得 field_label 可读信息，保留原主键值；被排除或无读取权限的源字段不额外输出标签。指定 _fields/RESTQL 查询不自动扩展其他展示字段。

generate_crud 输出 resource_options.py；把 RESOURCE_OPTIONS 导入本应用 AppConfig 并设置 resource_options = RESOURCE_OPTIONS 才会生效。fields.json 是生成时模型快照，不是运行配置。配置关联选择仍查询目标实体已授权的 table_data；关联反查使用下述 relation_info 新接口，旧 get_relation_info 拼写没有另设兼容入口。

AdminPermission 位于 core.permissions，允许超级管理员或启用的 admin 角色，供明确需要管理平台权限的独立接口使用；正常业务继续 ApiPermission。ORM 审计继续显式 request，软删除完整保存正常更新修改时间。

## 可选前端静态角色菜单

web/src/navigation.ts 默认 mode='backend'。改为 frontend 并填写 menus 时，角色按个人资料 role_info 中的 key 筛选；未通过角色的父节点及其后代不进入导航。菜单结构沿用 store.ts 的 Menu：实际 id、parent_id、路由及组件等字段必须完整，roles 为可选角色 key 数组。超级管理员可见全部配置菜单。

这是前端导航配置，不能授予 API 权限。首次账户加载仍先注册菜单并解析当前路由，之后挂载页面。当前已通过类型检查和构建，静态模式全部角色组合尚未浏览器验收。

关联选择单选清空为 null、多选清空为 []；新增关联配置字段通过“保存字段并选择关联”取得真实记录 ID 后再选择。FilePicker 库内删除调用既有文件删除接口，要求 file:delete 权限；媒体预览手机宽度随视口缩小。

## 第 19—22 批：资源、配置与组件扩展

通用菜单 component='system/Resource'，resource 填真实实体（如 post），component_name 填权限前缀（如 custom_post）；按钮生成保存 resource，按钮值保持 custom_post:list，API 仍是 /api/system/post/。静态 Menu 配置同样填写 resource。菜单保存或生成按钮后重新加载动态菜单；已有缓存标签的所有组合仍以实施文档待验范围为准。

子工作区可传 context 和 contextLabel；直接路由可传 menu_title/parent_title。标题缺省显示父项 ID，不读取额外父详情。

AppConfig.resource_options 示例（字段替换成真实模型字段）：

```python
resource_options = {
    'Entry': {
        'crud_fields': ['code', 'name', 'summary', 'amount'],
        'exclude_fields': ['internal_note'],
        'serializer_exclude_fields': ['secret'],
        'fields': {
            'summary': {'source': 'name', 'title': '摘要', 'kind': 'text'},
            'amount': {'column': {'minWidth': 180}, 'form': {'col': {'span': 12}}},
        },
        'crud_options': {'search': {'col': {'span': 12}}},
    },
}
```

crud_fields 决定 UI 字段顺序，UI 排除不隐式改变接口。fields 中非模型字段作为只读字段，source 是真实模型属性（包括可调用属性），授权继续跟随源字段；不是自由执行字符串。column/form/crud_options 在前端深合并。JSON 配置不执行 JavaScript；函数扩展使用自己的 TypeScript 组件及正常 DRF 覆写。

GET /api/system/system_config/relation_info/?var_name=关联变量&table=post&relation_ids=1,2 返回所有匹配配置分组及其正常可读子配置，匹配目标实体和真实主键，支持 SQLite JSON 单值与数组。当前身份的配置范围继续生效。
