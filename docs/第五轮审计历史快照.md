## 每项差异、证据及最小整改

### F01 · P1 · 接口排除字段被展示配置重新加入

归类：当前扩展契约整合缺口。证据：内存接口实测。

同一字段既在 serializer_exclude_fields 中，又在 fields 中设置标题/展示配置时，CoreSerializer 先删除字段，再把它补成 ReadOnlyField。独立岗位配置排除 code 后仅为 code 设置标题，详情仍返回 code=AUDIT-ONLY，状态 200。接口排除没有生效；这不是只排除 UI 的 exclude_fields 行为。

整改：按现有三个配置项的定义处理优先级：API 排除决定序列化字段是否存在，展示定制只作用于允许输出的字段。验证排除与标题/source/列配置组合，不加入新的排除规则。

[字段构造顺序](H:/Project_python/django-vue3-admin/djangovue3/backend/core/api.py:17)；[扩展契约](H:/Project_python/django-vue3-admin/djangovue3/docs/框架扩展与组件接入.md:82)。

### F02 · P1 · xlsx 导出未接通虚拟字段与用户字段排除

归类：当前扩展与 Excel 整合缺口。证据：内存接口实测 + 共用调用链。

配置 Post.summary 的 source=name 时，详情可正常返回摘要，但同步导出在 model_fields[summary] 抛 KeyError。Users 排除 mobile 后，固定 USER_EXPORT 仍索引该序列化字段，也抛 KeyError。异步导出在提交任务前复用同一列构造，所以同样受影响。默认实体导出已完成，不应因此写成“Excel 整体未实现”。

整改：沿用 openpyxl/xlsx，按有效序列化字段构造导出列，明确只读虚拟 source 的导出取值；用户固定列与实际字段集合相交。分别验普通字段、虚拟字段、被排除字段以及同步/异步输出。

[导出列](H:/Project_python/django-vue3-admin/djangovue3/backend/system/excel_fields.py:42)；[同步与异步共用列](H:/Project_python/django-vue3-admin/djangovue3/backend/system/excel.py:144)；[原用户专用导出](H:/Project_python/django-vue3-admin/django-vue3-admin-master/backend/dvadmin/system/views/user.py:167)。

### F03 · P1 · 部门用户和角色成员仍有额外接口权限依赖

归类：原有效流程未完整复刻。证据：内存接口实测 + 前端调用顺序。

普通角色有 user:list，可以直接查询部门及下级用户（200），但部门 info 为 403。含下级开关先调用 departmentSummary，统计成功后才刷新用户，因此合法筛选被统计接口阻断。角色有 role:users-get，成员接口为 200，RoleUsers 挂载却先等 dept/tree（403）才加载成员；全局 403 处理还会跳转 /401。原 all_dept 是登录可用的字典接口，dept_info 单独放行。上轮去掉父标题详情请求没有覆盖这两个分支。

整改：拆开筛选与统计依赖，并为成员部门筛选使用与该业务授权相符的选项来源；保持原有数据范围。用仅有子页面/成员读取权限的普通角色验收，不给角色附加整套部门管理权限来掩盖问题。

### F04 · P1 · 关联选择调用特殊资源时缺少视图动作上下文

归类：当前关联实现整合缺口。证据：内存接口实测。

关联表目录允许选择 dictionary、message_center 等实体。table_data 手工创建对应视图，只设置 request/format_kwarg，没有 action；两类视图的 get_queryset 读取 self.action，实际抛 AttributeError。原关联表能力存在；当前新增的统一目录在这些已列出的目标上未闭环。

### F05 · P2 · 关联保存键与反查键的定义不一致

归类：原关联能力与当前契约整合缺口。证据：内存接口实测，真实 id 对照通过。

关联设置和 TableSelect 允许 primarykey=code 并实际保存岗位业务编码，relation_info 却总按模型真实 pk 转换输入和已保存值。保存 AUDIT-ONLY 后反查得到 400“应该是一个整型”。真正按 id 保存/反查的对照为 200。现有文档选择“真实主键”，但配置界面与存值仍允许另一种语义；不是旧 URL 拼写兼容问题。

整改：优先保留原可配置业务键能力，沿配置 primarykey 统一存值/回显/反查。现方案“仅真实主键”与 UI 仍允许 code 不一致，不能通过新增禁止 code 规则掩盖。明确 relation_ids 是该配置键的值，使用该字段的正常转换，不吞错为空结果。

### F06 · P2 · 关联路径布尔筛选未按终点字段转换

归类：当前通用查询整合缺口。证据：内存接口实测，顶层多值对照通过。

顶层 status__in=true,false 已返回 200，但 user 的 role__status=true、role__status__in=true,false 返回 400。通用过滤只检查路径首段 role 的模型类型，没有解析最后的布尔字段。原自定义过滤和本次通用 ORM 查询协议并不完全相同；本项是当前已接受关联路径的查询实现不一致，不宣称原项目支持所有任意深度查询。

整改：沿关系路径解析实际查询字段，再转换布尔及多值参数；复用到列表、更新模板和异步导出。处理正常字段类型即可，不扩大成任意查询限制系统。

[通用查询转换](H:/Project_python/django-vue3-admin/djangovue3/backend/core/api.py:89)；[原过滤实现](H:/Project_python/django-vue3-admin/django-vue3-admin-master/backend/dvadmin/utils/filters.py:203)。

### F07 · P2 · 缓存路由继续使用旧资源参数

归类：当前菜单缓存整合缺口。证据：产品函数 + Vue VNode 实测。

cachedPage 按路径和刷新版本保存一个组件，setup 闭包捕获首次 Component VNode。同路径菜单由 post 改成 user、重新加载动态路由后，缓存封装仍渲染旧 VNode。直接执行产品函数及 Vue VNode：第二次传入 user，返回封装的 entity 仍是 post。Resource 页面已有的 props 监听接收不到新参数；手动刷新清缓存能绕过，但不等于菜单修改立即生效。

整改：保留缓存状态时更新当前渲染参数，或在菜单资源/组件映射变化时仅失效对应缓存。验菜单保存、路由重注册、账户切换与旧标签，不做每次跳转全量清缓存。

[缓存封装](H:/Project_python/django-vue3-admin/djangovue3/web/src/App.vue:30)；[重注册与 props](H:/Project_python/django-vue3-admin/djangovue3/web/src/router.ts:17)；[资源页面](H:/Project_python/django-vue3-admin/djangovue3/web/src/pages/Resource.vue:2)。

### F08 · P2 · 停用的缓存资源页会接收其他页面查询参数

归类：当前页面状态整合缺口。证据：实际 watch 回调 + Vue KeepAlive 渲染器实测。

ResourceTable 无页面归属判断地 watch 全局 route.query。KeepAlive 停用页面的普通 watch 继续运行。用 Vue 自定义渲染器真实切到 B，再改变 B 的 dept 查询，缓存 A 的 parent=7 被覆盖为 dept=42，并调用刷新。产品 updateContext 还会清勾选。因此缓存字典/树页面的筛选与选择可能被另一页改变。此处已验证 Vue 生命周期和实际回调，未声称完成浏览器全组合复现。

整改：让各资源页仅同步属于自己的路由上下文，保留各标签原来的树位置、筛选和勾选。验带参数/不带参数页面互切及共享标签配置。

[全局查询监听](H:/Project_python/django-vue3-admin/djangovue3/web/src/components/ResourceTable.vue:129)；[刷新并清选择](H:/Project_python/django-vue3-admin/djangovue3/web/src/components/ResourceTable.vue:118)；[缓存宿主](H:/Project_python/django-vue3-admin/djangovue3/web/src/App.vue:100)。

### F09 · P2 · 外链占位符与路由落地页未完整复刻

归类：原导航能力未完整复刻。证据：产品函数实测 + 两版导航源码。
