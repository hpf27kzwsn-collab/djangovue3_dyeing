## 本轮进一步对齐的业务逻辑

| 内容 | 当前行为 |
| --- | --- |
| 消息中心 | 用户/角色/部门/全员四种目标；创建即生成接收记录；再次发布不重复；管理列表按创建者范围，个人收件接口与最新消息不依赖消息管理菜单权限，详情读取标记本人已读 |
| 下载中心 | 普通用户只查询自己的下载任务，超级管理员查看全部；真实导出保存大小与 MD5 |
| 菜单/部门排序 | 上移下移在同一父节点内交换，包括原 sort 相等的情况；拖动按兄弟节点重排 |
| 字典 | 对齐文本、数字、日期、日期时间、时间、附件、布尔、图片八种类型；旧布尔记录迁移为类型 6；根字典标识唯一 |
| 系统配置 | 分组 key 与子 key 分开保存，访问名为 group.key；status 表示前端公开；后端使用不受公开开关影响；公开接口不要求 JWT，过期请求头不阻断；组内 key 和根 key 唯一；数组改为逐行编辑 |
| 关联配置 | 保留 table/primarykey/field/searchField；分页搜索、多页选择、选中值按配置显示字段展示；复用目标实体权限范围 |
| 区域 | 保留启用状态；新增/修改名称自动生成拼音、首字母及层级；初始化不覆盖已有启用选择 |
| 用户和岗位 | 用户类型为后台/前台；岗位状态为离职/在职，保持原枚举语义 |
| 实时消息 | fetch-event-source 实际连接 SSE，响应 text/event-stream、忽略协议注释心跳、提示新增消息；连接错误正常显现并按库机制重连 |
| Excel 依赖 | 将 FastCrud 引入的旧 npm xlsx 替换为官方 CDN 0.20.3，保留依赖许可；npm audit 为 0 项已知漏洞 |
